# 缩裹基线 STL 资产

MEMFLOW 专项（`16C-06` 有界逐层流式内存根治）的**内存与耗时基线资产**，
同时可用作缩裹工艺的真实测试用例。

## 为什么需要这批资产

上游专项原用 `123.stl`，但该资产**已不存在**（仓库与项目资料目录下均搜索不到），
且上游要求的可复现快照从未形成。其文档记载的数字（Grid 5197 x 1418 x 141、
约 10.39~11.00 亿 pixel-layer、六通道约 5.8~6.1 GiB、17 个连通分量）
**只能作容量参考，不可再引为实测基线**。

本批 8 个 STL 的栅格与 pixel-layer 与 `123.stl` 同量级，故作为其替代。

## 命名

```text
<类型>-<代号>.stl

类型   suoguo         单缩裹
       qiegejiapian   需切割甲片
代号   两到三个小写字母，与原始文件的来源标识一一对应
```

原始文件名含**真实客户姓名**，入库前已脱敏为代号。**本文件不记录代号与姓名的对应关系** —— 
记录了脱敏就失去意义。如需追溯，见原始目录
`E:\项目资料\自研打印机测试数据\修复后的obj文件\缩裹测试-2\<姓名>\`（不在版本控制内）。

## 规模与基线

采集口径：`Release` 构建、单材料工艺（STL 不携带材质与贴图）、
DPI 635x600、层厚 0.038mm、MATVOL 关闭、**串行无并发**。

栅格均为 5501 x 1418（`qiegejiapian-hcc` 为 5626 x 1418），层数 104~138。

> `autoOrient` 实测会做 `identity_rotate_z_minus_90` 旋转，X/Y 互换后栅格为
> 1500 x 5197 量级，**列数总量不变**，故 pixel-layer 结论不受影响。

## 这批数据的用途

**一、MEMFLOW 的 A 侧基线。** G-M7 的验收判据是「同请求 Release 峰值内存下降」，
在此之前 A 侧一直缺失（上游 REPORT 标为 `INPUT SNAPSHOT PENDING`）。
MF-07 生产路由接入后可直接用本表做 A/B。

**二、印证专项前提。** 决策文称「主要问题不是三角形数量」，本批数据直接支持：

```text
峰值内存 vs pixel-layer   相关系数 +0.996
三角数 12,084 -> 241,274（20 倍），峰值仅 2,853 -> 3,316 MB（1.16 倍）
```

> 注意别只看相关系数：峰值对三角数的相关系数是 +0.864，看着也高，
> 但那是因为三角数最多的样本恰好幅面也最大，属**假相关**。
> 正确判据是上面「20 倍对 1.16 倍」的对照。

**三、缩裹工艺测试。** 它们本身是真实生产用例。但注意 STL 不携带材质，
缩裹识别当前按 `Kd` 精确匹配，故这批资产**无法直接用于 T 通道识别测试**。

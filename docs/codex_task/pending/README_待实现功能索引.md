**为什么值得做**：268 项回归目前全靠人工本机跑。`AGENTS.md` 里那两条醒目警告
（构建与回归必须分开判定退出码；根下 `build/` 是陈旧目录）**本身就是没有 CI 的症状**——
干净 checkout + 单一构建目录 + 退出码即结论的环境里，这两个陷阱根本不会存在。

**本轮新增的支撑材料**（真要开工时可直接用，省掉重新测量）：

  CI 的分层策略可以直接照搬这三档，不必重新设计。
- `-j` 的安全边界已量清：起进程/Qt 的测试在并行下墙钟膨胀 10~25 倍并撞自己的内部期限，
  所以 CI 上**并行度不能照抄构建侧的 16**，需要按档设定（详见 `analysis/04` 的「VSCode 三档验证」）。
- 稳定失败集当前为 **4 项**（R-06 闭环后由 5 降为 4），CI 的初始基线可直接取这 4 项。

## 3. PF-00 瓶颈定位（COMPLETE）

### 3.1 定位方法（可复现）

每次切片的 stderr 末尾输出 `SLICE_TIMING`，各阶段耗时齐全，**先看它再动手**：

```text
gridSetupMs        MATVOL plan 构建 + relief 采样   ← P1 前占总耗时 95%~98%
layerComputeMs     逐层材质所有权解算
layerComposeMs     逐层通道合成（含补白、光油 pass）
tiffWriteMs        TIFF 编码写盘
previewWriteMs     预览 PNG
outputWriteMs      报告与包发布
totalMs            总计
```

### 3.2 P1 前的实测（串行无并发）

| 资产 | 顶点 | 面数 | 材质 | 栅格列数 | gridSetupMs | totalMs | gridSetup 占比 |
|---|---|---|---|---|---|---|---|
| gubao04 | 80,691 | 104,170 | 6 | 192,960 | 265,035 | 269,880 | **98.2%** |
| tm2-5 | 31,349 | 37,401 | 4 | 175,770 | 70,482 | 73,920 | 95.3% |
| yz | 18,844 | 20,477 | 2 | 191,700 | 25,596 | 37,456 | 68.3% |

### 3.3 根因：四层嵌套，无空间剔除

`src/slicer_core/materials/volume/MaterialVolumePlan.cpp` 的逐列求交主循环：

```cpp
for (y = 0 .. heightPx)                                  // 行
  for (x = 0 .. widthPx)                                 // 列
    for (material = 0 .. materialCount)                  // 材质
      for (triangleIndex : trianglesByMaterial[material]) // 该材质【全部】三角
          PointInTriangleXy(px, py, a, b, c, ...)         // 三次叉积
```

内两层合计即全模型三角数，故复杂度为 **O(列数 × 三角数)**，与材质数无关
（材质只是把三角分了组，总遍历量不变）。

> **归因更正：** 实施方最初按「材质数 × 面数」估算 gubao04/tm2-5 的耗时比为 4.18×，
> 与实测 4.34× 接近，但那个归因是**错的**。正确因子是「列数 × 面数」，
> 材质数因子纯属巧合。后续若据此估算务必用正确模型。

### 3.4 量化：99.99% 的判定必然落空

按三角 XY 包围盒覆盖的像素数统计：

```text
gubao04   当前比较 104,170 × 192,960 = 20,100,643,200 次
          包围盒内约                      2,002,945 次
          三角平均覆盖 19.2 列，占栅格 0.0100%   → 理论上限约 10,036×

tm2-5     当前比较  37,401 × 175,770 =  6,573,973,770 次
          包围盒内约                      1,069,144 次
          三角平均覆盖 28.6 列，占栅格 0.0163%   → 理论上限约 6,149×
```

复现脚本见 §7。

## 4. P1 三角 XY 包围盒剔除（COMPLETE，`ec37adf`）

### 4.1 改动

预计算逐三角 XY 包围盒（一次 O(三角数)，gubao04 约 3.3MB），内层循环先做四次比较
排除落空三角，再进入原有三叉积判定。

### 4.2 为何不改变判定结果（勿改此性质）

点落在三角形内 ⟹ 点落在其 XY 包围盒内。故以**闭区间**包围盒剔除是保守的，不会漏命中。
包围盒 min/max 取自 `PointInTriangleXy` 所用的同一组顶点坐标，**不引入 epsilon 收缩**，
因此恰压在像素中心线上的边界三角仍会进入原判定。

### 4.3 实测收益

| 资产 | gridSetupMs | 加速 | totalMs |
|---|---|---|---|
| gubao04 | 265,035 → **40,819** | 6.5× | 273 → **50 s** |
| tm2-5 | 70,482 → **15,048** | 4.7× | 75 → **22 s** |
| yz | 25,596 → **8,771** | 2.9× | 39 → **24 s** |

实际 6.5× 远低于理论上限 10,036×，因 gridSetup 还含交点排序、奇偶配对、重叠检测、
区间物化等工作，且剔除自身有成本。**这说明剔除已把「求交」这一项压到不再主导，
剩余耗时属其它工作** —— 这是判断 P2/P3 性价比的关键依据。

## 6. P2 / P3 的触发条件与选择依据

### 6.1 何时启动

满足**任一**条即值得启动：

```text
T1  真实使用中某资产 totalMs 超过可接受阈值（建议 120 s），且
    SLICE_TIMING 显示 gridSetupMs 占比仍 > 60%
T2  出现面数 > 30 万的资产（gubao04 的 10 万面在 P1 后为 50 s，
    线性外推 30 万面约 150 s，届时 gridSetup 会重新主导）
T3  栅格列数显著增大（更高 DPI 或更大幅面），因复杂度含列数因子
```

**不满足上述条件时不要动。** P1 已使 gridSetup 不再是唯一主导项，盲目继续优化
plan 构建可能把工时投在已非瓶颈的位置。

### 6.2 先做诊断，再选方案

```text
步骤 1  串行、无并发跑一次目标资产，取 SLICE_TIMING
步骤 2  看 gridSetupMs 占比
          > 60%  → 继续本专项，进 6.3 选 P2 或 P3
          < 60%  → 瓶颈已转移，改看 layerComposeMs / tiffWriteMs，
                   本专项不适用，应另立专项
步骤 3  用 §7 脚本量化三角平均覆盖列数
          覆盖列数大（三角稀疏而大）→ P1 剔除效果已接近上限，选 P3
          覆盖列数小但三角极多       → 选 P2
```

### 6.3 两个方案

| | P2 XY 均匀网格分桶 | P3 循环反转为三角光栅化 |
|---|---|---|
| 做法 | 按 XY 把三角装桶，每列只查所在桶 | 遍历三角 → 投影到它覆盖的列（与 relief 采样同形态） |
| 预期 | 在 P1 之上再 3~10× | 接近理论上限 |
| 改动量 | 中等（建桶 + 查桶 + 跨桶三角处理） | 较大（重写主循环结构） |
| 风险 | 低。仍是「先剔除再原判定」，可保持零漂移 | **中高**。逐列交点的收集顺序改变，须保证排序与奇偶配对结果等价 |
| 内存 | O(三角数 + 桶数) | 需逐列交点累积缓冲，注意 MV-03 边界 |

**P3 有现成先例**：`sample_relief_heightfield_masks`（`slicer.cpp:1355` 附近）就是
「遍历三角、投影到覆盖像素」的形态，同一份几何在 relief 那一遍很快。P3 本质是把
plan 构建对齐到该形态。实现时应参照它，而非从头设计。

### 6.4 P3 的关键风险点（若启动，先解决这一条）

当前实现按列收集交点后 `std::sort` 再奇偶配对。循环反转后交点是按三角顺序散落到各列的，
**必须保证每列最终的交点多重集与排序结果和反转前完全一致** —— 包括共面、共享边造成的
重复命中的合并行为（现实现有 `merged` 去重逻辑）。零漂移验证必须覆盖含共面/共享边的资产
（`tm2-5` 的四材质靠共享界面互补封闭，是现成样本）。

## 7. 量化脚本（复现 §3.4）

```python
import numpy as np
def analyze(path, wpx, hpx):
    V=[]; F=[]
    for line in open(path, errors='ignore'):
        if line.startswith('v '):
            p=line.split(); V.append((float(p[1]),float(p[2])))
        elif line.startswith('f '):
            idx=[int(t.split('/')[0]) for t in line.split()[1:]]
            F.append([i-1 if i>0 else len(V)+i for i in idx])
    V=np.array(V)
    xmin,ymin=V.min(axis=0); xmax,ymax=V.max(axis=0)
    sx=(xmax-xmin)/wpx; sy=(ymax-ymin)/hpx
    total=sum(((V[f][:,0].max()-V[f][:,0].min())/sx+1)
             *((V[f][:,1].max()-V[f][:,1].min())/sy+1) for f in F)
    cols=wpx*hpx
    print(f'三角={len(F)} 列={cols} 当前比较={len(F)*cols:,.0f} '
          f'剔除后≈{total:,.0f} 上限≈{len(F)*cols/total:.0f}x '
          f'平均覆盖{total/len(F):.1f}列')
```

栅格尺寸取自输出 TIFF 的 `width × height`。

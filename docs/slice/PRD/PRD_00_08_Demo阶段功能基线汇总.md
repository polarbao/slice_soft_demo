## 1. 文档目的

本文件把 00-08 阶段从“历史碎片”整理为当前正式项目可读的功能基线。

00-08 的目标不是继续新增需求，而是回答：

```text
demo 阶段已经证明过哪些能力；
哪些能力是后续 09P / 10 / 11 的基础；
哪些历史能力需要保留回归；
哪些内容只是历史验证，不应被误认为当前正式产品能力。
```

---

## 2. 阶段功能总览

| 阶段 | 功能主题 | 当前正式意义 |
|---|---|---|
| 00 | 单材料体素切片与 RGBWSV 多通道输出 | 建立最小切片输出闭环 |
| 00A | P0 demo 增强、预览导入、几何鲁棒性 | 补足 demo 可观察性和输入鲁棒性 |
| 00B | 8bit 输出与黑色打印极性 | 固定 `uint8` 与 `black_is_print` 基线 |
| 00C | 单材料浮雕切片修正 | 建立 relief heightfield 的正确性基线 |
| 01 | 2.5D 浮雕正式切片路线 | 将 relief 从 demo 修正为正式路线 |
| 02 | 支撑、孤岛检测、SupportType | 建立支撑与诊断基础 |
| 03 | RGBWSV 协议固化与负向测试 | 固定 `p0.rgbwsv.2` 的协议红线 |
| 03B | TIFF storage mode 兼容 | 支持 stripped / tiled 等存储模式兼容 |
| 03C | 回归脚本拆分与 reader 摘要输出 | 建立回归分层和输出摘要能力 |
| 04 | OBJ / MTL / PNG 彩色纹理 | 建立彩色纹理采样与 RGB 输出 |
| 04A | 纹理 fallback 与支撑诊断修复 | 让缺失纹理和支撑割裂可诊断 |
| 05 | MaterialPolicy / 白墨 / 光油策略 | 建立 W / V 通道策略基础 |
| 05A | MaterialProcessProfile 真实材料参数 | 让材料工艺参数可配置、可报告 |
| 06 | 3MF 与 OBJ/MTL 多材料输入 | 建立多格式、多材料输入基础 |
| 06A | 3MF deflate / XML / bad package | 建立 3MF 兼容性和负向测试 |
| 06B | 3MF Texture2D / ColorGroup | 扩展 3MF 纹理和颜色组支持 |
| 07 | Qt Debug UI 基础版 | 建立调试 UI 和工程观察入口 |
| 07A | 参数编辑与 profile 可视化 | 将配置和 profile 可视化进入 UI |
| 07B | UI smoke / 配置编辑器收口 | 建立 UI 自动化验证基础 |
| R0/R1/R2 | 架构审查、模块边界、配置报告测试 CI | 将 demo 推向正式工程结构 |
| 08 | 支撑形态与工艺优化 | 深化支撑形态、工艺和诊断 |
| 08A | 支撑桥接 fixture 与真实模型 profile | 建立真实模型支撑验证收口 |

## 3. 00-08 对后续阶段的支撑

```text
09P 依赖 03 的 RGBWSV 协议、04/06 的纹理输入、05 的材料策略、08 的支撑诊断；
10 依赖 03 的输出协议、04/06 的纹理来源、05/05A 的材料工艺、07/R2 的报告和验证；
11 依赖 07/07A/07B 的 Qt UI、R2 的配置报告、03/04/05/06/08 的层数据和通道语义。
```

---

## 4. 当前边界

00-08 汇总不是新需求入口。后续开发不应从旧阶段重新展开，而应：

```text
保留已验证行为；
避免破坏 RGBWSV 协议；
用当前代码和测试确认实现状态；
将新需求放入 09P-R2、10、11 或后续阶段。
```

---

## 5. 非目标

```text
不恢复旧 docs/slicer 作为当前入口；
不为 00-08 每个子阶段重新生成单独 PRD/DEV；
不把历史报告当作当前代码已通过验证；
不引入 RIP、设备通信或喷头 bitstream。
```

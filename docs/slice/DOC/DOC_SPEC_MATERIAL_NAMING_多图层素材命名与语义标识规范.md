## 1. 命名格式

本节常规 `-L<n>` 格式适用于实际打印素材。唯一非打印定位保留名为精确的 `nail-Default`，见 §1.3；普通 `Default` 不属于例外。

```text
<素材名>[-<同层序号>]-L<图层号>

图层号     从【最上层】起为 1，依次向下递增：L1、L2、L3 …
同层序号   仅当该层【同类素材有多个】时才写；只有一个时省略
分隔符     半角连字符 `-`，前后不留空格
```

### 1.0.1 同层序号（用户 2026-09-03 补充）

同一图层内同类素材有多个时（例如第一层前后两块互不相连的透明区域），用序号区分：

```text
该层同类素材唯一   trans-L1                    省略序号
该层同类有多个     trans-1-L1  trans-2-L1      带序号
```

**序号只用于区分，不参与优先级计算。** 同层同类素材在工艺上等价，理应共享同一
priority；若它们在空间上真有重叠，由 MATVOL 自身的同级重叠阻断兜住，而不是凭序号
臆造出工艺上并不存在的覆盖关系。

因此自动优先级对同层同类的多个素材算出**相同数值**，这是预期结果，不按撞号处理。
只有「不同层或不同类却算出同值」才判为撞号并 fail-closed。

> **约束：素材名主体不得以 `-<数字>` 结尾。**
> 语法上无法区分「同层序号」与「素材名本身以 -数字 结尾」，解析一律把尾部
> `-<正整数>` 视为序号。若素材确需数字结尾，请改用其它连接方式（如 `nail2`）。

序号取不带前导零的正整数（`-1`、`-2`、…）；`-0` 与 `-01` 都不接受，避免同一素材
出现两种写法。序号不必连续、也不要求与几何前后顺序对应——它只是标识。

示例（两图层，每层一个透明素材 + 一个不透明素材）：

```text
trans-L1     图层 1（最上层）的透明素材
sg-L1        图层 1 的不透明素材
trans-L2     图层 2 的透明素材
sg-L2        图层 2 的不透明素材
```

带同层序号的示例（`gubao04/gb04`，三图层六素材，实测通过）：

```text
trans-L1     图层 1 的透明素材（该层仅一个，省略序号）
nail-1-L1    图层 1 的第 1 块不透明素材   贴图 002_1.png
nail-2-L1    图层 1 的第 2 块不透明素材   贴图 002.png
trans-L2     图层 2 的透明素材
nail-L2      图层 2 的不透明素材           贴图 003-2.png
nail-L3      图层 3 的不透明素材           贴图 001.png
```

其自动优先级（`max_layer = 3`）：

```text
trans-L1  = (3+1-1)*100 + 20 = 320
nail-1-L1 = (3+1-1)*100 + 10 = 310   ┐ 同层同类，共享同一 priority
nail-2-L1 = (3+1-1)*100 + 10 = 310   ┘ 这是预期结果，不按撞号处理
trans-L2  = (3+1-2)*100 + 20 = 220
nail-L2   = (3+1-2)*100 + 10 = 210
nail-L3   = (3+1-3)*100 + 10 = 110
```

实测六个素材各自都拿到了像素（129 层，未归属 0，无错误）：

```text
nail-1-L1  278,913     nail-L2   68,236     trans-L1  390,110
nail-2-L1    4,752     nail-L3  639,867     trans-L2  589,755
```

### 1.0.2 贴图素材的命名权归设计侧（用户 2026-09-08 裁定）

**除下列特殊素材外，需要贴图的素材由设计侧自行命名，切片侧不约束其名字主体。**

| 特殊素材 | 保留写法 | 说明 |
|---|---|---|
| 透明材料 | `trans` / `transparent` | 落 V（光油），见 §6.2 N6 |
| 非打印定位素材 | `nail-Default` | 精确保留名，区分大小写，见 §1.3 |
| 缩裹材料 / 弹性材料 | `el` / `elasticity` | 落 T，见 §6.2 N7 |

`-L<n>` 层号后缀**仍然强制**（它承载设计层序，是自动 priority 的唯一依据）；
放开的只是**名字主体**。

**为什么必须放开（实测来由，`gubao-xin`）：** 该资产每一层有两块几何**共用同一份
贴图数据、仅 UV 坐标不同**。它们必须是两个 `newmtl` 才能各自绑定自己的 UV，
于是设计侧自行命名为：

```text
L1   lcb-L1 (暗夜古堡4.png)    cb-L1 (暗夜古堡4_2.png)
L2   lsg-L2 (暗夜古堡3.png)    sg-L2 (暗夜古堡3_1.png)
L3   Isg-L3 (暗夜古堡2.png)    sg-L3 (暗夜古堡2_3.png)
```

（每对的两张 PNG 字节数相同，即同一份图像数据。注意 `Isg-L3` 首字母是**大写 I**
而 `lsg-L2` 是**小写 l** —— 多数字体下肉眼难辨，排查时请以字节为准。）

**旧规则拦不住也留不得：** §1.0.1 的同层序号只承认「同一素材的多块」
（`<素材名>-<序号>-L<层号>`），要求基名相同；上面三对基名各不相同，
原实现逐对判为 priority 撞号，**整份资产被拒**（`E_MATOPQ_LAYER_PRIORITY_COLLISION`）。
故本次把判据放宽为「同层同类即可共享 priority，与素材名是否相同无关」。

**放宽为什么不会引入静默错误（已读实现确认，非推断）：** 同层同类在工艺上等价，
若两者在空间上**真有重叠**，`MaterialVolumePlan` 在构建期逐列阻断并点名两个材质
（`MaterialVolumeErrorCode::OverlapUnresolved`，消息为
`materials 'A' and 'B' overlap with equal priority at (x, y)`）。
**兜底在 MATVOL，不在命名层。** 并列分区（各占一部分 XY、互不重叠）是正常情形，
本来就该通过。

`nail-Default` 仍是精确保留名，**不因本次放宽而放松**：它不带层号、不参加 priority，
且大小写敏感（`nail-default`、`Nail-Default` 都不是它）。

#### 1.0.2.1 实测（`gubao-xin`，600 DPI / 0.033 mm / 147 层，2026-09-08）

修复后八个打印素材各自都拿到像素，未归属为 0、无错误：

```text
trans-L1  724,565    lcb-L1  130,018    cb-L1    85,640
trans-L2  558,400    lsg-L2   38,332    sg-L2    50,876
                     Isg-L3  277,463    sg-L3   366,407
unownedModelPixels = 0    errors = []
```

自动优先级（`max_layer = 3`）：

```text
trans-L1  = 320
lcb-L1    = 310   ┐ 同层同类，共享 priority —— 本次放宽后的预期结果
cb-L1     = 310   ┘
trans-L2  = 220
lsg-L2    = 210   ┐
sg-L2     = 210   ┘
Isg-L3    = 110   ┐
sg-L3     = 110   ┘
```

#### 1.0.2.2 同时修掉的第二个缺口：`nail-Default` 未从命名解析中排除

`materialInfos` 来自 **MTL 解析**而非面绑定，故即使导入期
`ExtractFrameGeometry` 已把定位面从网格剥离，`nail-Default` 仍出现在材质表里。
它没有 `-L<n>` 后缀，原实现据此判违规，**在撞号之前就先把资产拒了**
（实测 `gubao-xin` 的首个报错正是
`E_MATOPQ_LAYER_NAME_INVALID: material 'nail-Default' does not end with the required -L<n> layer suffix`）。

现已在 `ResolveMaterialLayerNaming` 中整体跳过该保留名：不报违规、不计入
`max_layer`、不产生 overlap 规则 —— 与 §6.3 原本的表述一致（该表述此前只在
导入层成立，切片侧并未落实）。

> **为什么 FRAME 验证没暴露这两点：** `gubao05` 每层只有一个常规素材
> （`nail-1-L1` / `nail-L2` / `nail-L3`），碰不到同层多素材；而它的验证走的是
> 宿主/Worker 路径，与 CLI relief 路径下 `auto_by_material_name` 的这段解析不同路。

#### 1.0.2.3 一条排查提示（非本次缺陷）

复现期间在 300 DPI / 0.3 mm 的粗网格下遇到
`E_MATVOL_MODEL_PIXEL_UNOWNED: model pixel at column N has no material owner`，
**但它在已验证的 `gubao05` 上同样复现**，换回 600 DPI / 0.033 mm 后两个资产都通过。
故该报错是**采样分辨率过粗导致 relief 逐列采样与 MATVOL 区间不一致**，
不是资产或命名问题。排查这类报错时请先确认分辨率与层厚，再怀疑资产。

## 1.1 L<n> 是【设计语义】，不是物理 Z 位置（用户 2026-09-01 补充）

```text
设计侧固定语义   L1 永远是设计上的最上层，L2 在其下，依次递增。
                 该编号【由设计意图决定】，与模型在切片软件中的朝向无关。

切片侧可能反转   autoOrient 会对模型做右角度旋转/翻转以压低高度，
                 反转后【物理上 L2 可能位于 L1 之上】。
                 这不构成矛盾，也不需要重新编号。
```

**为何反转不影响 priority（实现依据，勿改）：**

```text
priority 只在【材质体积重叠时】参与裁决，回答的是
「设计意图上谁应当覆盖谁」，不是「谁的 Z 更高」。

两个材质体积是否重叠属几何事实，模型反转后它们【仍然重叠】，
重叠关系不随朝向改变；而设计意图同样不随朝向改变。
故 L1 优先级最高应读作「L1 是设计上的表面层，重叠时覆盖下层」，
【不得】读作「L1 在 Z 轴上更高」。

推论   ResolveMaterialLayerNaming 只看材质名，不看几何、不看朝向，
       这是刻意的：一旦让它感知 Z，autoOrient 就会改变材质归属，
       同一份资产在不同摆放下会切出不同产物。
```

## 1.2 内嵌关系必须用【不同层号】表达（用户 2026-09-02 裁定）

当一个素材被另一个素材**完全包裹**（内层的 X/Y/Z 范围都真包含于外层之内）时，
两者**不得使用同一层号**，且**被包裹者层号必须更小**：

```text
正确   nail-L1  + trans-L2     被包裹的物体 L1，包裹它的介质 L2
错误   nail-L1  + trans-L1     同层 —— 被包裹物体会被静默压掉
```

### 1.2.1 为什么同层会失效

同层时 priority 由类别次序决定，而透明类别的次序高于常规素材：

```text
两个都标 L1（max_layer = 1）
  trans-L1 → (1+1-1)*100 + 20(transparent) = 120   胜
  nail-L1  → (1+1-1)*100 + 10(regular)     = 110   被压掉

改为 trans-L2（max_layer = 2）
  nail-L1  → (2+1-1)*100 + 10 = 210   胜（层序主导）
  trans-L2 → (2+1-2)*100 + 20 = 120
```

类别次序在**并列分区**场景（两素材各占一部分 XY，仅边界重叠）是正确的——
透明覆盖区应判光油。但在**内嵌**场景它会反过来吃掉被包裹的物体。
**修正方式是分层，不是改类别次序**（改次序会破坏并列分区场景的既有行为）。

### 1.2.2 实测依据（`yz/bg-test01`，2026-09-02）

资产为「透明块内嵌一个带贴图物体」：

```text
材质        Z 范围            XY 范围                            关系
trans     -9.0000 ~ 9.0000   [-8.00,-10.00] ~ [10.00, 8.00]    外层
nail      -4.1481 ~ 4.5000   [-4.76,-4.41] ~ [ 6.76, 5.62]    完全被包在内部
```

同一几何、仅改材质名，切片结果（474 层）：

```text
A  trans-L1 + nail-L1    R=0 G=0 B=0  V=90,623,675
                         非光油 RGB 像素 = 0        内嵌物体完全消失
B  trans-L2 + nail-L1    R=2,938,793 G=B=2,939,331  V=87,684,271
                         非光油 RGB 像素 = 2,939,331  唯一色 15,096   内嵌物体正确显示且带贴图
```

### 1.2.3 当前实现不会拦截该错误（已知缺口）

方案 A 的切片**退出码为 0、无任何告警**——内嵌物体消失是静默的。

原因：`MaterialLayerNameResolver` 的实现纪律是「只看材质名，不看几何与朝向」
（否则 autoOrient 翻转会改变材质归属），因此它在命名解析层**无法**判定内嵌关系。

故本规则目前**依赖设计侧遵守**。建议的自动兜底见 §7。

## 1.3 非打印画幅定位保留名（用户 2026-09-07 授权）

所有只用于确定输出画幅、不实际打印的定位素材，统一精确使用材质名：

```text
nail-Default
```

这是用途保留名，不是常规打印材质名，不带 `-L<n>`，不参加图层 priority 推导。同一定位材质可以绑定多个定位块；OBJ 的 `usemtl` 与 MTL 的 `newmtl` 必须一致。普通 `Default`、大小写近似的 `nail-default`/`Nail-Default`、追加层号的 `nail-Default-L1` 均不属于此精确保留名，不能自动忽略。

该保留名的识别**区分大小写**，不同于 §6.2 中打印材料类别词的大小写等价规则。也不根据模型文件名、定位块尺寸、颜色或透明度猜测用途。

### 1.3.1 设计侧导出示例

必须修改的是**绑定在定位面上的材质名**，仅将 OBJ 文件名或对象名改为 `nail-Default` 不会生效。

MTL 中声明定位材质（其他材质参数按原资产保留）：

```text
newmtl nail-Default
```

OBJ 中在定位块的面定义之前引用它；开始主体面时切回主体自己的打印材质：

```text
usemtl nail-Default
# 后续为定位块的 f 面定义，沿用原顶点和面索引
usemtl nail-L1
# 后续为主体的 f 面定义，沿用原顶点和面索引
```

以上仅展示材质绑定切换，不是完整 OBJ。多个定位块共用一个 `nail-Default` 材质，
不要改成 `nail-Default-1` 或 `nail-Default-L1`，也不要把需要打印的主体面绑定到它。

### 1.3.2 输出与兼容边界

定位几何只扩展与主体应用相同变换后的 XY 输出包围范围，不参与主体自动定向决策、触底参考、打印层高、纹理、RGBWSV/T 材料或支撑；其独占区域保持不喷墨。定位块不再作为打印表面出现在模型预览中，画幅范围仍保留。只含定位几何的作业必须拒绝，不能生成空白“成功”生产包。

该规则同时适用于“多图层透明”和“全实体 RGB+按需补白墨”，不替代主体的工艺配置。
修改源素材后需要重新导入。当前含定位几何的可选修复导出会以
`E_FRAME_REPAIR_UNSUPPORTED` 拒绝，避免导出的修复资产静默丢失画幅；正常切片不受此导出限制。

**源姿态不等于自动定向结果。** “定位不参与定向决策”是指只根据打印主体计算方向，
不是保证与旧版把定位块也当主体时得到同一方向。“导入时自动定向”仍默认勾选，
可能翻转主体；“导入后自动排版”也仍默认勾选，会调整落位。
若需要保留设计侧的倒钩姿态与源 XY，导入前取消这两个勾选，并将批次原点 X/Y 设为 0；
宿主仍将打印主体沿 Z 触底。只需保留姿态、允许自动落位时，仅取消自动定向即可。

该规则已由 FRAME 专项实施；gubao05 的 600 DPI / 0.033 mm、148 层完整软件切片及定位空区/独立严格 Reader 验证通过，Release 运行时已部署。GUI 人工交互与物理打印不在已验证范围。技术方案见 `DOC_DESIGN_FRAME_非打印定位素材与输出画幅分离.md`；状态和实际 Gate 见 `TASKS_FRAME_非打印定位素材与输出画幅专项任务清单.md`。其他实际打印材质的命名和严格拓扑准入不变。

|---|---|---|---|---|


## 3. 与既有术语的对应

```text
弹性材料 = 缩裹材料 = transfer = T 通道 = elasticity / el
  （权威定义见 DOC_DECISION_MATVOL_T §3.0，通道字母 T 取自「弹性」拼音首字母）
透明素材 = 光油 = V 通道 = transparent / trans
  （光油判据见 DOC_DECISION_MATOPQ §7 C1：d <= opacityMax）
```

## 4. 对切片侧的作用（逐项说明能解决什么）

### 4.1 能解决：素材可区分

```text
问题   多图层的同类素材此前无法区分。
       tm3 的两层不透明素材同名为 sg (3) / sg (2)，且旧解析器把两者截断为同一个 sg；
       tm2/tm3 的两层透明素材【共用同一个 touming】，连名字都相同。
解决   -L<n> 后缀使每个素材在全模型内唯一。
依赖   MO-06 已修的整行取名（材质名不再被空格截断），已随本专项落地。
```

### 4.2 能解决：`overlap.rules` 的优先级可自动生成

```text
问题   MATVOL 要求逐材质【显式声明】priority，同级 fail-closed、缺声明 fail-closed。
       4 素材需要 4 条规则，靠人工填写不可持续。
阻碍   此前无法按名推导层序——tm2-3 的 touming-2 位于【上层】、touming-1 位于【下层】，
       编号与层序【反向】，任何按名字数字推层序的逻辑都会推反。
解决   -L<n> 规范把层序写进名字且方向确定（L1 = 最上层），可可靠推导。

自动生成公式（已实施，MaterialLayerNameResolver）
  层步长     (最大层号 + 1 - 本层号) * 100     ← 层序【主导】
  类别次序   弹性 el 30 ｜ 透明 trans 20 ｜ 常规 10   ← 仅在同层内区分
  priority   层步长 + 类别次序

  【2026-09-02 修正】本行原写作「弹性 30 ｜ 常规 20 ｜ 透明 10」，
  与实现相反。实现见 MaterialLayerNameResolver.cpp：
  kElasticityRank=30 / kTransparentRank=20 / kRegularRank=10。
  透明必须高于常规的工艺理由（代码注释原文）：光油「盖在彩色之上才有意义；
  若让彩色压过光油，那块区域的光油等于没打」。弹性材料是结构件，仍居最高。

两图层示例（同步修正，原示例四行的 trans/nail 次序与实现相反）
  trans-L1   (2+1-1)*100 + 20 = 220
  nail-L1    (2+1-1)*100 + 10 = 210
  trans-L2   (2+1-2)*100 + 20 = 120
  nail-L2    (2+1-2)*100 + 10 = 110

  该组数值与 tm2-5 实测一致（见 MATOPQ 任务卡自动模式对照：
  自动生成的 rules 与手写 rules 六通道全部 +0 差异）。

为何层序必须主导（实测教训，2026-09-01）
  首版公式把【类别】设为主导（类别间隔 100、层序间隔 10），
  两图层时 nail-L2(210) 反而压过 trans-L1(120)，
  实测导致 1993 个像素本应归光油却落入 RGB。
  L1 是设计上的表面层，其光油必须覆盖 L2 的彩色——
  故层步长必须远大于类别间隔。该错误由端到端对照实测发现，
  单测只验证「公式算得对」，验不出「公式设计得对」。

  注   上述 210 / 120 是【首版公式】下的数值，首版的类别次序亦与最终实现不同，
       故不可用本节的当前公式复算。当前公式的数值见上方两图层示例，
       并由 tests/unit/material_layer_naming 断言（sg-L1=210、trans-L1=220）。

约束   同层同类的多个素材共享同一 priority，【不】按撞号处理 ——
       与素材名是否相同无关（2026-09-08 放宽，见 §1.0.2）。
       真重叠由 MATVOL 构建期的同级阻断兜住，不靠命名层。

       注   当前公式下「不同层或不同类却算出同值」【不可能发生】：
            priority = (max+1-layer)*100 + rank，rank ∈ {10,20,30}，
            故 |rank 差| <= 20 < 100，priority 相等必然意味着层号与类别都相同。
            解析器仍保留 collision 检查，作为公式改动的绊线，当前不可达。

       沿革   该行原写作「priority 必须全局唯一」，与 2026-09-03 的同层序号规则
              矛盾；2026-09-03 改为「同层同类同名才共享」；2026-09-08 再放宽为
              「同层同类即共享」，因为贴图素材命名权已归设计侧。
```

### 4.4 多图层贴图/纵深表达（**已由 MATOPQ-RGB 解决**，2026-09-02 更新）

> 本节原记为「不能解决」。MATOPQ-RGB 专项（M1+M2）已解决，结论随之更新。

```text
       被顶面遮住的下层材质取不到自己的 UV，实测表现为「下层贴图不出现」。
```

```text

M1     唯一色      1  = (167,243,255)    归属修正为 nail 自身 Kd，仍为单色
```

### 4.5 对透明→光油识别是**冗余但有价值**

```text
现状   MO-04 的光油判据用 MTL 的 d 值（d <= opacityMax），【不依赖名称】。
```

## 5. 已确认口径（用户 2026-09-01 回签）

```text
A1  常规素材的【名字主体】不约束，但 -L<n> 后缀【必须带】。
    即「素材1-L1」中 `素材1` 可自由命名，`-L1` 是强制后缀。
    否则无法推导层序，§4.2 的自动 priority 生成失效。

A2  单图层模型【也必须带 -L1】。
    使解析逻辑无需区分单层与多层两套分支，降低分歧面。
```

**由此得到的强制规则（设计侧必须遵守）：**

```text
R1  每个实际打印的 usemtl 材质名都必须以 -L<n> 结尾，n 为正整数，L1 = 最上层。
    非打印定位精确保留名 nail-Default 见 §1.3，不能推广为忽略所有 Default。
R2  透明素材的名字主体必须为 transparent 或 trans。
R3  缩裹/弹性材料的名字主体必须为 elasticity 或 el。
R4  常规素材名字主体自由，但不得与 R2/R3 的保留词冲突。
R5  同一模型内材质名必须唯一（由 -L<n> 天然保证同类不重名）。
R6  【同一图层内的所有素材必须使用同一个层号】。
    即上层写 nail-L1 + trans-L1，下层写 nail-L2 + trans-L2；
    不得出现同层素材层号不一致（如 nail-L1 与 trans-L2 实为同层）。
```

**R6 的来由（实测暴露，2026-09-01）：**

```text
tm2-4 的四个材质为 nail-1 / trans-2 / trans-1 / nail-2：
  nail 的编号为 1,2（顺序），trans 的编号为 2,1（倒序）。
由此产生两种互不相容的层序读法：
  解读A（数字即层号）  L1={nail-1, trans-1}  L2={trans-2, nail-2}
  解读B（段序成对）    L1={nail-1, trans-2}  L2={trans-1, nail-2}
实测两种解读【产物不同】：V 相差 321 像素（占模型 0.012%），
两者守恒均成立、都是合法产物，仅那 321 像素归光油或归彩色不同。
用户 2026-09-01 裁定采用【解读 A】。
R6 的作用是让此类歧义在源头不再出现——命名本身即自解释，无需任何人推断。
```

### 6.3 自动 priority 公式（由 N1..N5 推导，无需手填 `overlap.rules`）

本公式仅处理实际打印材质。`nail-Default` 在导入时已分离，不参与最大层号或 priority 计算。

```text
priority = (max_layer + 1 - layer) * 100 + 类别次序
类别次序   elasticity 30 ｜ transparent 20 ｜ regular 10

层序主导，同层才比类别。反例警示：若改为类别主导，
nail-L2(210) 会压过 trans-L1(120)，实测造成 1,993 像素错归。
```

**同层序号不参与计算，素材名也不参与。** 同层同类的多个素材算出**相同** priority，
这是预期结果，**无论它们是否同名**（`trans-1-L1` 与 `trans-2-L1` 是同名多块，
`lcb-L1` 与 `cb-L1` 是不同素材，两种都共享）：它们工艺上等价，硬分先后会臆造出
不存在的覆盖关系。若二者空间上真有重叠，由 MATVOL 构建期的同级重叠阻断兜住
（`OverlapUnresolved`，逐列点名两个材质）。

因此同层同类共享优先级不报错。而「不同层或不同类却算出同值」在当前公式下
**不可能发生**（rank 差 <= 20 < 100），解析器保留该检查仅作为公式改动的绊线。

启用方式：`materialVolumePolicy.overlap.mode = "auto_by_material_name"`，且 `rules` 必须为空。

### 6.4 多图层贴图的三个必要条件

```text
1  命名合规（N1..N5）
2  materialVolumePolicy.enabled = true，mode = closed_intervals
3  geometrySampling.degenerateAreaEpsilonMm2 = 1e-24
缺一不可。三者齐备后，各图层各自的 map_Kd 均能正确采样（§4.4 实测）。
```

## 7. 已知缺口与建议（2026-09-02）

### 7.1 内嵌同层错误无法自动拦截

N5 目前**依赖设计侧遵守**。`MaterialLayerNameResolver` 的实现纪律是「只看材质名，
不看几何与朝向」（否则 autoOrient 翻转会改变材质归属），故命名解析层无法判定内嵌关系。

实测后果：`yz/bg-test01` 按 A 方案（同层）切片，**退出码 0、无告警**，内嵌物体完全消失。
这属于本专项一直在根治的「静默丢弃设计意图」那一类缺陷。

### 7.2 建议的自动兜底（**未实施，需用户授权**）

不判断「内嵌」，只检测结果异常：

```text
若某个在 overlap 中声明了 priority 的材质，在整个输出中占 0 像素
  → 出诊断（该材质被完全压掉，通常意味着层号写错）
```

优点：无需几何分析，不违反「只看材质名」纪律，且能一并捕获层号写错、
priority 撞号等多种误配。属于新增校验，会改变部分资产的可切性或产出告警，
故**不在本专项范围内擅自实施**。

# REPORT HOSTFLOW H-F-14 导入自动排版开关与源坐标审计

> 状态：**H-F-14 COMPLETE / H-F-15 已后续完成**
> 日期：2026-09-04
> 范围：参考宿主导入落位与源坐标审计；不修改冻结 SPI、生产切片或模型文件

## 1. 当前实现

“变换与排版”页新增默认勾选的“导入后自动排版”：

- 勾选：导入成功后按当前 11×2、列/行净距参数调用一次权威 `applyGridLayout`；
- 取消：不调用 `applyGridLayout`，保留模型导入并自动定向后的当前 X/Y 坐标；
- 手动“执行规则排版”始终可用；
- 开关是宿主进程内状态，编辑开关不跨 DLL，也不改变场景 revision；
- 导入仍默认触底，Z 坐标不按 OBJ 原值保留。

默认保持勾选是为了不改变既有操作流；需要观察模型自带排布时由操作员主动取消。

## 2. 坐标系统结论

当前设备画幅为 `origin=lower_left`、X/Y 正向、`230×100 mm`。OBJ 没有单位声明，当前导入合同按
`modelTransform.unit=mm` 解释顶点。因此在不进行 X/Y 旋转和平移时，OBJ 数值坐标 `(0,0)` 与画幅
左下原点 `(0,0)` 是同一个数值原点。

但“坐标系原点一致”不等于“模型包含原点”：本次 10 个 OBJ 均没有 X/Y 同时为 0 的顶点，整个
模型集合的最小 Y 为 1.5065 mm，因此几何本身不经过 `(0,0)`。

## 4. 为什么关闭排版仍不能严格恢复源排布

公共 `model.import` 当前固定使用默认 `autoOrient.enabled=true`。10 个模型中 5 个发生自动定向：

| 模型 | 导入定向 | 导入定向后的 XY 结果 |
|---|---|---|
| segment_102 | `rotate_y_180 + rotate_z_180` | Y 变为负值 |
| segment_103 | `rotate_y_180` | X 变为负值 |
| segment_104 | `rotate_y_180` | X 变为负值 |
| segment_105 | `rotate_z_180` | X/Y 均变为负值 |
| segment_204 | `rotate_z_180` | X/Y 均变为负值 |

其余 5 个保持 `identity`，但 `segment_205` 本身仍有约 0.5002 mm 的左越界。自动定向绕全局原点旋转，
所以仅关闭网格排版无法保证“严格按 OBJ 源坐标显示”。UI 文案因此明确写成“导入定向后的 XY”。

## 5. 后续严格源姿态方案

若产品需要完整复现这批 OBJ 的源排布，应新增 H-F-15，以受控方式给冻结的
`model.import.options` 增加显式且默认关闭的源姿态模式。metadata 与模块保留的 SceneModel 必须共用
同一 `autoOrient.enabled=false`，并验证未知字段拒绝、旧请求默认兼容、ViewData/预检/切片几何一致。

不能只在宿主侧根据包围盒逆算旋转：宿主不应复制模型解析/定向数学，而且包围盒不足以恢复模型姿态。
H-F-15 后续已获用户授权并完成，见
`REPORT_HOSTFLOW_H_F_15_自动定向开关与批次原点偏移.md`。本报告仍保留 H-F-14 当时的审计结论。

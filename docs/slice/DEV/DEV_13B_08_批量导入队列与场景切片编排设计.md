# DEV 13B-08 批量导入队列与场景切片编排设计

> 文档版本：v1.1
> 文档状态：APPROVED
> 日期：2026-07-28
> 批准记录：2026-07-28，用户授权按原子任务实施

## 1. 设计目标

在不绕过现有 Scene/Admission/Package 边界的前提下，把 Qt 多模型俯视场景接到 13B 联合切片核心，
同时支持一次选择多个模型文件。

## 2. 模块边界

```text
MainWindow / SceneActionBar
  -> SceneBatchImportController (Qt orchestration)
      -> ModelTopViewLoader (existing async single request)
      -> SceneDocument / SceneModelRepository
      -> grid layout once per completed batch

MainWindow / SceneSliceActionController
  -> SceneTransformController::SaveSceneEffectiveConfig
  -> ScenePreflightService
  -> slicer_cli --scene-config <scene_config.effective.json>
      -> MultiModelProductionService (no Qt)
          -> MultiModelSliceOrchestrator
          -> SceneLayerComposer
          -> WriteMultiModelSceneProductionPackage
  -> ProductionPackageResultValidator
  -> PackageLoader / PreviewWorkspace
```

Qt 只负责文件选择、状态呈现和进程生命周期。多模型生产业务必须位于 `slicer_core` 或 CLI 应用层，
不得把矩阵 Fixture 逻辑复制进 `MainWindow.cpp`。

## 3. 批量导入控制器

建议新增：

```text
apps/slicer_debug_ui/controllers/SceneBatchImportController.h/.cpp
```

职责：

```text
接收规范化文件列表；
冻结 batchId、初始 sceneRevision 和剩余容量；
串行产生 ModelTopViewLoadRequest；
等待当前请求终态后再启动下一项；
记录逐文件 imported/failed/cancelled；
全部完成后执行一次 grid layout；
发出批次摘要和进度信号。
```

采用串行队列而不是并发 22 请求，原因是 `ModelTopViewLoader`、SceneDocument revision 和纹理资源提交
当前均按单请求设计。P0 先保证确定性与低峰值内存；后续有 profile 证据再考虑有限并发。

建议 DTO：

```text
SceneBatchImportRequest：batchId/files/capacity/autoLayout；
SceneBatchImportItemResult：path/modelId/instanceId/status/error；
SceneBatchImportSummary：selected/imported/failed/cancelled/finalSceneRevision。
```

## 4. 文件对话框与队列

`MainWindow::OnImportModelPreview()` 改用 `QFileDialog::getOpenFileNames()`。返回后先完成：

```text
去除空路径；
规范化绝对路径；
校验扩展名；
校验总数不超过剩余容量；
保留返回顺序；
一次性提交控制器。
```

模型列表工具栏的“添加”按钮和顶部“导入模型”必须调用同一入口，不维护第二套导入行为。

## 5. 场景生产服务

建议新增无 Qt 边界：

```text
src/slicer_core/pipeline/MultiModelProductionService.h/.cpp
```

服务输入为已回读验证的 `scene_config.effective.json` 和显式输出目录。职责：

```text
读取并校验 scene effective config schema/hash/revision；
加载每个可见实例资源；
校验 scene-wide Profile、buildVolume 和 pipeline mode；
调用逐实例 adapter/orchestrator；
执行全局层合成；
调用共享 Scene Package writer；
返回稳定进度、错误和 package identity。
```

CLI 增加显式入口：

```powershell
slicer_cli --scene-config <scene_config.effective.json>
```

不复用含义模糊的单模型 `--config` 自动猜 schema，避免错误文件进入错误管线。CLI 应保持现有单模型入口
兼容。

## 6. 场景预检和模式

Qt 点击主动作后：

1. 冻结当前 scene/transform/Profile/mode identity；
2. 自动写入并回读 `scene_config.effective.json`；
3. 对每个可见实例执行所选模式预检；
4. 执行 buildVolume、碰撞、revision 和 transform hash 校验；
5. 全部通过后才启动 CLI；
6. 任一失败返回 instanceId + 稳定错误码。

Legacy 和 Global 必须显式分流。若当前 Global 多模型生产 Gate 未关闭，返回
`SCENE_PIPELINE_MODE_NOT_ADMITTED`，不得切换到 Legacy。

## 7. Qt 主动作

建议新增轻量组件：

```text
apps/slicer_debug_ui/widgets/SceneActionBar.h/.cpp
apps/slicer_debug_ui/controllers/SceneSliceActionController.h/.cpp
```

`SceneActionBar` 只显示：

```text
导入模型；
保存场景；
模式/Profile 摘要；
切片当前场景；
取消；
单行状态。
```

`SceneSliceActionController` 负责状态机：

```text
Idle -> Snapshotting -> Preflighting -> Slicing -> Validating -> LoadingResult
     -> Completed / Blocked / Failed / Cancelled。
```

MainWindow 只连接信号槽，不承载各阶段业务判断。

## 8. 输出和回载

成功后必须先经 `ProductionPackageResultValidator` 验证 scene/package/session identity，再调用
`LoadPackageSummary()`。失败或 stale 结果不得覆盖当前场景状态。

场景在进程运行期间被修改时：

```text
当前进程可继续使用冻结快照；
结果标记为基于旧 revision；
不得把旧结果表示为当前场景已切片；
用户可打开结果，但下一次切片必须重新冻结快照。
```

## 11. 验证策略

```text
controller unit：顺序、容量、部分失败、取消和单次排版；
core unit：scene effective config 到联合层和单 package；
CLI process：--scene-config 正负向和退出码；
UI Smoke：批量导入 3 个模型、主按钮状态、成功回载；
matrix：1/3/11/12/22；
RIP strict：所有正向 package；
legacy single-model：原入口不回归；
Quick CI / Debug full / Release targeted。
```

## 12. 风险

| 风险 | 控制 |
|---|---|
| 直接启用旧按钮绕过 Scene | 新建显式 scene route，旧单模型入口保持禁用条件 |
| 批量异步 revision 竞争 | 串行队列、batchId、expected revision |
| 部分失败造成用户误判 | 固定批次摘要，不静默跳过 |
| 22 模型峰值内存 | 串行导入、资源仓库复用、记录峰值 |
| 设备幅面未知 | 正式 production fail-closed；fixture 明确标识 |
| Global 能力不足 | 显式阻断，无 fallback |

# DECISION-03：放开 RGBWSVT 单实例护栏的授权

> 专项：MONOWRAP ｜ 日期：2026-09-20 ｜ 对应任务：[TASKS-03](TASKS-03-缩裹整版多实例.md) MW3-06
> 依据：[ANALYSIS-04](ANALYSIS-04-缩裹整版多实例的根因与实现面实测.md)
> **本文先于代码改动写成。** 放开 fail-closed 护栏必须留痕，不能实现完了再补。

## 1. 要放开的是什么

两道，都是 fail-closed，互为纵深：

| # | 位置 | 错误码 | 时机 |
| --- | --- | --- | --- |
| ① | `apps/slicer_worker/slice/WorkerSliceRequestMaterializer.cpp:405` | `PM-SLICER-LAYOUT-0022` | Worker 物化请求时，执行前 |
| ② | `src/slicer_core/engine/ProductionSliceFacadeFactory.cpp:287` | `PM-SLICER-LAYOUT-0023` | 核心生产入口，执行中 |
| ③ | `src/slicer_core/materials/transfer/LegacyTransferChannelSession.cpp:15` | `E_MATVOL_T_PROTOCOL_INVALID` | `run_slicer` 入口（**盘点时漏了，实施中撞出**） |

两道说的是同一句话：`slice.rgbwsvt` 要求场景里**恰好一个可见实例**。

## 2. 它们当初为什么存在

**不是保守，是诚实。** matvol-t 立项时 RGBWSVT 根本没有多实例合成器——
`RunTransferProductionEntry` 挑出唯一可见实例后直接调单模型 `run_slicer`
（`engine_version` 老实写着 `legacy-rgbwsvt-scene-v1`）。

护栏挡住的是「**声称支持整版、实际只切了一件**」这种静默错误。
`DOC_PREP_MATVOL_T_T_06:85` 的 T-06B 验收条件原文：

> 03 单实例成功；**多实例**/08/09/取消均 **fail closed** 且无残包

所以这两道不是可有可无的挑剔，它们是那一期**能力边界的诚实声明**。

## 3. 凭什么现在可以放开

护栏的前提是「没有多实例合成器」。该前提在本批被消除：

| 证据 | 内容 |
| --- | --- |
| MW3-01/02 | 整版缩裹掩膜在合成器内顺带合成，复用其摆放与跨实例裁决；2 条用例经**双向**故障注入证伪且互相可区分 |
| MW3-04 | 整版七通道装配走**现有** `ComposeRgbwsvtLayer`，端到端用例经故障注入证伪 |
| ANALYSIS-04 §6c | 跨实例 T×T / T×V 落在**既有**的 `InstanceOverlap` / `MaterialConflict` 拒绝路径上，不需要新写拒绝逻辑 |
| MW3-01 字节基线 | 六通道产出 11 例 / 738 产物逐字节一致，能力是**加上去的**，不是挪用来的 |

也就是说：护栏当初挡的那个静默错误，现在**不会发生了**——不是因为我们决定不挡，
而是因为被挡的那件事已经能正确完成。

## 4. 放开的**前置条件**（未满足即不得放开）

MW3-06 只有在下列各项全绿时才可落地，缺一即停：

- [x] MW3-05：入口已按可见实例数分流（**单实例不改道**，理由见 §4b）
- [x] MW3-07：七通道整版包能完整写出，并通过专用回读自检（清单统计与 TIFF 字节对账）
- [x] MW3-09：**单实例**缩裹产出对 MW3-00 快照逐字节一致（4115 产物）
      > 唯一差异是快照脚手架自身的运行目录名（`before`/`after`），它被写进
      > `manifest.json` 与 `package_report.json` 的 `configPath`/`packageDir`。
      > 处理办法不是「看一眼觉得没事就放过」：把两边运行根换成同一占位符后
      > **要求整份文件完全相等**，相等即证明差异恰好只有那条路径、再无其它。
- [x] MW3-10：12 件整版实跑，一个包；**与单材料光油对拍**通过——12 实例、23 层、
      75574 个打印像素，V 与 T 逐像素几何完全相同且 T 像素前六通道全空
- [x] MW3-12：全量档 275 项、失败集合 == 基线 4 项；字节级基线 PASS（738 产物）

> 第三项尤其要紧：放开护栏**不得改变单实例的行为**。
> 若单实例产出变了，说明改道动了它本不该动的东西，此时应当先查，而不是放开。

## 4b. 两道护栏分两次放（2026-09-20 实施时追加）

实施 MW3-05 时撞出一个次序问题：**分流本身就等于放开核心那道护栏②**，
而第 4 节的前置条件里有三条（MW3-09/10/12）只有在分流存在之后才跑得了。
鸡生蛋。

解法是把两道拆开放：

| 护栏 | 处置 | 时点 |
| --- | --- | --- |
| ② 核心 `PM-SLICER-LAYOUT-0023` | 改成**按可见实例数分流**：0 仍拒绝，1 走原路，>1 走整版 | MW3-05，已实施 |
| ① Worker `PM-SLICER-LAYOUT-0022` | **留着**，作为外层闸门 | MW3-06，待第 4 节全绿 |

也就是说：核心已具备整版能力、可被单测与实跑验证，但**整条端到端路径
仍被 Worker 那道挡着**，用户从 UI 点下去还是会被拦下。
等 MW3-09/10/12 验完再摘 ①，那才是真正的「放开」。

> 这样排的好处是前置条件仍然是**硬**的：MW3-09 要比对的单实例产出，
> 此刻已经能在核心侧跑出来了，不必为了验证而先放开端到端。

### 单实例不改道，是被这条前置条件倒逼出来的

原打算让 `RunTransferProductionEntry` 整个改道走多模型服务。真要那样，
单实例的字节必然变——换了合成器、换了写包器、画幅从模型包围盒变成整版画布。
那就只能回头去放宽第 4 节那条「逐字节一致」，而它本来就是用来兜住
「改道动了不该动的东西」的。

**宁可多一条分支，也不要把自己定的判据改松。**

## 5. 明确**不**放开的

| 项 | 理由 |
| --- | --- |
| 模型像素跨实例重叠 | 仍由 `InstanceOverlap` 整单拒绝。这是六通道一直以来的约束，非缩裹独有 |
| 模型内 V/T 同像素 | `slicer.cpp:1124` 的 `E_MATOPQ_VARNISH_TRANSFER_OVERLAP` 保持 fail-closed。K3 邻域表决仍未实施，且**当前无重叠资产可验证它**——跑不到的裁决不如显式拒绝 |
| `slicer_cli` 直出包的生产准入 | `rgbwsvt_candidate_unvalidated` 标记不动。CLI 直出仍不算已准入生产包 |
| 零可见实例 | 仍然拒绝。整版切片至少要有一件 |

## 6. 授权

用户 2026-09-20 就整版缩裹的诉求裁定：

> 仿照之前 `单材料光油`、`白墨` 的方式进行切片处理，切片之后是一个最大外包围区域

以及对后续任务的放行：

> 可按照你的建议进行后续任务的处理

「仿照光油/白墨」即要求 RGBWSVT 取得与 `p0.rgbwsv.2` 同等的整版能力，
而该能力与这两道单实例护栏在语义上**互斥**：护栏不放开，诉求无法满足。
故本文据此授权 MW3-06，**以第 4 节的前置条件为限**。

## 7. 回滚

放开后若发现整版产出有误，回滚是**把两道护栏改回原样**即可——
它们是独立的前置检查，不与合成/装配逻辑纠缠。
MW3-01/02/04 新增的掩膜出口在 `platemasksink` 未设置时零分配、零行为改变，
故即便护栏回滚，那部分也可以留在树上不必一并撤回。

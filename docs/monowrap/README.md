## 1. 缘起

用户 2026-09-20 提出两件事：

1. 导入 `model/obj/alg_suoguo/20260908-HuangChenC` 下的文件，
   希望**输出为单缩裹材料**，但现有预设工艺里没有对应选项，能否新建工艺文件。
2. 缩裹材料的自动识别当前依赖 mtl，**单材料情况下无法只把模型识别为缩裹材料**。

## 2. 上下文速览（全部 A 级，细节见 ANALYSIS-01）

### 2.1 资产是纯几何，零材质引用

| 项 | 实测 |
|---|---|
| 目录构成 | **10 个 `.obj`，0 个 `.mtl`** |
| `mtllib` / `usemtl` | **一条都没有**（10 个文件全查过） |
| 单件规模 | 3 049 ~ 7 029 顶点 / 6 094 ~ 14 054 面 |
| 整盘包围盒 | **174.0 × 58.2 × 5.6 mm**，分两排，XY 两两重叠 **0 对**——已排好版 |
| 几何可用性 | `--inspect-model` 通过，autoOrient 正常，**问题不在几何** |

同目录另一组样本 `黄晨晨-算法缩裹/` 同样是 10 个 obj、无 mtl。**这是这类资产的常态。**

### 2.2 一处必须先更正的表述

缘起里说「识别是根据 mtl 中素材命名」——**这对一半**。本仓有两条互不相干的路径：

| 路径 | 依据 | 能产出的角色 |
|---|---|---|
| 按名字 `map_input_material_to_role` | `matchNameContains` 子串 | Rgb / White / Varnish / Ignore / SupportCandidate / Support——**没有缩裹** |
| 按颜色 `ResolveTransferMaterial` | 漫反射 RGB **精确匹配** | T 通道（缩裹） |

且 `TransferMaterialResolver.h` 明确写明材质名**永不**用作 transfer 角色配置，
这是刻意的设计决定。**所以「改成也支持按名字识别缩裹」不是本专项的方向。**

### 2.3 核心认识：不必发明新概念

`nail_varnish_only_rgbwsvt.json` 里已经有 `varnish.mode = "all_model"`、
`white.layers = "all_model"`——**白墨与光油早就支持整模应用，唯独 T 通道没有。**
要补的就是这个。

### 2.4 真正的阻碍在体积求解那一层

`MaterialVolumePlan.cpp:144-149` 对空材质名**直接抛错**
（`"mesh contains triangles without a bound material"`），
而目标模型的三角形全部无材质名。**「空筛选器等于整模」救不了**——
筛选器确实是空的，但网格里的三角形本身没有材质名，在这道检查就被拒。

## 3. 裁定结果（用户 2026-09-20：「按照你的建议进行开发处理」）

| 门 | 裁定 | 一句话理由 |
|---|---|---|
| **G-1** | **方案 B**：T 通道内合成材质名 | 无材质网格该不该被体积求解接受是 MATVOL 的问题，本专项不替它决定 fail-closed |
| **G-2** | **方案一**：schema 同版本放宽 | 实质差别仅多一个枚举值，不值得新契约版本；双维护正是 F-53 那类漂移的温床 |
| **G-3** | **整盘一次切**（场景模式） | 坐标是资产自带的，逐件切会丢排版并产出 10 个没法当一个作业打的包 |
| **G-4** | **不成立** | `RgbwsvtProtocol.cpp:66` 把 transfer 值锁死为 0（`black_is_print`） |

依据与完整优劣比较见 [DECISION-01](DECISION-01-开工门四问的裁定与依据.md)。

## 4. 两个容易搞反的地方

**① 用户问题 1 依赖问题 2，不是并列。** 在整模识别落地前，
即使把工艺文件写出来，跑这批模型也只会得到**空的 T 通道**。
**不要先交一个工艺文件当作问题 1 已解决。**

**② G-2 已裁定不等于可以跳过前提。** 同版本放宽的放行前提是
「既有 738 产物基线逐字节不变」（MONOWRAP-03）。**该前提不过就要重新评估。**

### 一次关键的方向更正

初版让整模缩裹走体积求解，10 件资产只有 5 件能切。
**用户指出「单材料光油工艺能正常切这批模型」**，据此查明光油的整模模式
是在已栅格化像素上直接赋值、不经体积求解。改成同构做法后 **10/10 全通**，
且实现反而更小。细节见 [TASKS-01 §3.5](TASKS-01-任务清单.md)。

### UI 预设已落地（2026-09-20）

新增预设 **「单材料缩裹｜整模 T 实体｜下表面支撑」**（id `single_material_transfer_wrap`）。

它**自带 whole_model 策略**，不从部署目录派生——部署目录只提供全局唯一一条 T 策略，
放 whole_model 进去会破坏「部署工艺策略必须一致」的不变量。

为此追加了 C ABI 枚举值 `HOST_MATERIAL_TRANSFER_SOLID = 6`（**加法，向后兼容**），
并把同一个「matchSource 决定颜色列表要求」的判据补到了宿主侧的两处校验——
**这个假设在本仓一共硬编码了 5 处**：核心配置校验、核心解析器、报告 schema、
宿主工艺加载器、宿主 Profile 桥接。

清点断言按两类拆分（派生变体 vs 自带策略），**保住了它对「漏派生」的检出能力**，
而不是简单把数字加一。内容断言经故障注入证伪：把 `rgbEnabled` 打开即变红。

**开发分支**：`feature/claude-monowrap-whole-model-transfer`（分叉自 `develop/packaged-slicer`）。

## 6. 不在本专项范围内

| 项 | 理由 |
|---|---|
| 给 `MaterialRole` 增加「缩裹」角色 | 解析器头文件明确写明材质名永不用作 transfer 角色配置，推翻它须另立专项并出授权文档 |
| 放宽 `MaterialVolumePlan` 的空材质名 fail-closed | 那是 MATVOL 的决定范围（G-1 选方案 B 正是为了避开它） |
| 缩裹几何算法本身 | 本专项只解决「整模被识别为缩裹材料」 |

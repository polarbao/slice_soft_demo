## 2. 未执行，及各自的理由

### CFG-1 把 T 策略提为单文件 —— **收益最大，但改动面需要单独一轮**

要改加载器、**5 处 CMake/脚本拷贝点**、以及两条硬断言
（`files.size() == 10`、10 份策略一致）。这不是"顺手做掉"的体量，
混进本轮会让一次提交同时承载三件不相干的事。**建议单独立一条任务。**

### CFG-2 删 7 份无执行消费方的 T 副本 —— **依赖 CFG-1 先定**

若 CFG-1 落地，这 7 份自然不再进部署包，无需单独删；
若 CFG-1 不做而先删它们，三处循环断言都要改，且**我未实测删后行为不变**
（推断依据是 10 份策略一致，但推断不是验证）。**顺序上它应在 CFG-1 之后。**

### CFG-3 / CFG-4 合并 UI 预设 —— **会减少用户可见选项，不擅自做**

这两条合的是**用户在下拉里能选到的工艺**：

- CFG-4（G1）涉及 `DefaultPresetId()`，**改默认 id 会波及所有按 id 解析的调用方**；
- CFG-3（G2）合并后 `RgbWhiteVarnish` 失去唯一预设入口，
  且已保存的 workspace 若按 preset id 持久化可能失配（**我未验证**）。

更要紧的是：**"选项太多"是感受，"哪些该合"是产品判断。**
我能给出「它们只差一个枚举」这个事实，但"是否应该让用户少一个选择"不是我该替你定的。

### UX-1 把「导入落位与规则排版」从 tab 4 移到 tab 0 —— **收益最大，但要先有回归护栏**

这是四条不一致里**最严重**的一条（用户按标签顺序操作会发现勾选无效）。
但它是**面板搬迁**，要同步 `HostInspectorPages.h` 的分组，
而本仓的 UI 侧目前没有能覆盖"面板归属"的回归。
**建议先补一条断言面板归属的测试，再做搬迁**——否则搬错了没人拦得住。

### UX-5 `scene_admission` 的耗时记进 `gridSetupMs` —— **查下来不值得改**

调研里把它标为"命名错位"。实际查了消费方之后我不这么认为：

`gridSetupMs` 是 **CLI、worker、宿主共用**的键（`CliDiagnosticJson.cpp:65`、
`main.cpp:356`、`WorkerSliceExecutor.cpp:227`、`HostSliceJobPanel.cpp:387` 等），
在 legacy 路径下它名副其实。问题只在**宿主把场景路径的 admission 阶段复用了这一行**。

真修要么新增一个耗时键（波及 CLI 与 worker），要么做场景专属标签。
**为一个显示措辞付这个波及面不划算。** 记录在案，不改。

# 统一版本规则

> 适用组件：motionControlSDK；稳定组件 ID：`motion-runtime`；发布策略：`independent`；
> 版本方案：SemVer 2.0.0。

## 1. 版本对象

| 对象 | 含义 | 当前示例 | 权威来源 |
| --- | --- | --- | --- |
| 实现版本 | SDK DLL 的独立发布版本 | `1.2.0` | `version-manifest.json` |
| 完整构建标识 | 实现版本加源码、构建配置和依赖变体 | `1.2.0+g123456789abc.release.thirdparty-static` | 构建期生成 |
| API 契约版本 | 调用方头文件和公开 API 兼容边界 | `motion-sdk.api.v1.2` | `version-manifest.json` |
| 通信协议版本 | SDK 与下位机报文契约 | `motion-control.protocol.v1.1` | 协议文档及 manifest 兼容项 |
| 配置 Schema | INI 字段结构与迁移边界 | 由配置规范独立维护 | 配置文档/实现 |
| 第三方版本 | libhv、spdlog 等依赖版本 | vcpkg manifest/baseline | 当前为 `vcpkg.json`；引入自定义 registry 后再增加受控配置文件 |

这些对象不得混用。API v1.2 不等于通信协议 v1.2；Git revision 也不能替代实现版本。

## 2. SemVer 增长规则

格式：

```text
MAJOR.MINOR.PATCH[-PRERELEASE][+BUILD]
```

| 变化 | 动作 |
| --- | --- |
| 不兼容的公开 API、数据契约或部署边界变化 | 增加 `MAJOR` |
| 向后兼容地增加能力 | 增加 `MINOR` |
| 向后兼容地修复缺陷 | 增加 `PATCH` |
| 仅 Git revision 或 dirty 状态变化 | 只更新 build metadata |
| 候选阶段变化 | 使用 `dev`、`alpha.N`、`beta.N`、`rc.N` |

本仓库在建立统一版本事实源前没有受控 SemVer 稳定标签。首次治理版本先采用 `1.2.0-dev`
完成验证，并于 2026-08-05 冻结为稳定基线 `1.2.0`。从该基线发布后，后续破坏性公开 API
改造必须增加 `MAJOR`，不得继续只增加 minor。

## 3. 稳定组件身份与状态

`componentId` 固定为 `motion-runtime`，不得因 DLL 文件名、产品名称、UI 文案或组织调整而变化。
组件状态只使用：

```text
available
not-integrated
bundled-without-independent-version
unavailable
incompatible
```

未知或不可用状态不得伪装成 `0.0.0`。

## 4. 单一事实源

1. 实现版本、组件身份、发布策略和 API 契约只在根目录 `version-manifest.json` 维护。
2. CMake `project(VERSION)`、生成头文件、Windows 资源、CPack、SDK API、日志和测试软件从该事实源派生。
3. Git revision 与 dirty 状态在每次构建时刷新，不写回源码目录。
4. Debug/Release 不改变 SemVer 实现版本，但必须进入完整构建标识和构建 manifest。
5. 第三方静态/动态依赖属于制品差异，必须进入完整构建标识和构建 manifest。
6. 无法读取 Git 状态时必须报告 `unknown`，完整构建标识使用 `+source.unknown.<config>.<variant>`。
7. 编译时间只用于诊断，不参与版本或兼容性判断。

## 5. 发布标签

稳定版本使用 annotated tag：

```text
v<MAJOR>.<MINOR>.<PATCH>
```

`dev`、`alpha`、`beta` 和 `rc` 构建不得伪装成稳定标签。标签、manifest、发布包内构建
manifest 和 DLL 文件属性必须能互相核对。

## 6. 差异化编译登记

差异来源按以下方式进入版本身份：

| 差异来源 | 体现方式 |
| --- | --- |
| 已提交源码变化 | 12 位 Git revision 变化 |
| 未提交源码或构建脚本变化 | 增加 `.dirty` |
| Debug / Release | 增加 `.debug` / `.release`，并记录 `/MDd` / `/MD` |
| 第三方静态 / 动态依赖 | 增加 `.thirdparty-static` / `.thirdparty-dynamic` |
| vcpkg 构建环境 | 构建 manifest 记录 `targetTriplet` |
| 未来影响 ABI、协议或运行行为的编译开关 | 必须新增稳定 variant 标识和 manifest 字段 |

不应把所有编译器优化参数拼进 SemVer。只有会改变 DLL 行为、ABI、依赖部署或硬件协议路径的
选项才进入受控 build metadata；仅改变诊断详细度且不影响制品契约的选项记录在构建环境清单中。

## 7. 禁止项

1. 禁止根据 Git commit 数量、文件夹名、时间戳或 DLL 修改时间推导版本。
2. 禁止在 UI、日志、CMake 和源码中分别维护版本字符串。
3. 禁止版本查询触发 `MC_Init()`、设备连接或硬件命令。
4. 禁止把 build metadata 当作 SemVer 优先级的一部分。
5. 禁止把 Mock、NetAssist 或软件测试结果描述成真机验证通过。

# 09 配置系统详解

## 1. 配置从哪里来

当前有三种常见来源：

1. `samples/configs/**/*.json` 中的直接配置；
2. 带 `schema=slicer.config.1` 的包装配置，经 migration 变成 legacy root；
3. Qt 工作台由 Profile template + UI override 生成的会话 effective config。

无论来源如何，最终都进入 `SliceConfig`。教程以 `config.h` 默认值和 `config.cpp` 解析/校验为当前真源。

## 2. 最小配置

~~~json
{
  "input": {
    "modelPath": "samples/models/sample.stl",
    "format": "auto"
  },
  "output": {
    "packageDir": "output/SlicePackage"
  }
}
~~~

其余字段使用当前默认值。为了复现生产或测试结果，正式 Profile 应显式写出关键分辨率、层厚、通道、材料和安全设置，不要过度依赖未来可能调整的默认值。

## 3. 顶层配置地图

| 节点 | 责任 | 关键字段 |
|---|---|---|
| `slicingMode` | 几何切片类别 | `closed_mesh_scanline` / `relief_heightfield` |
| `input` | 输入资产 | `modelPath`、`format` |
| `output` | 包、网格、TIFF | package、DPI、层厚、通道、storage |
| `modelTransform` | 单位与姿态 | scale、rotation、translation |
| `autoOrient` | 自动朝向 | enabled、maxHeight、strategy |
| `background` | 空白值 | 当前应为 255 |
| `modelMaterial` | legacy 模型材料 | channel、applyMode、RGB/W/V 值 |
| `texture` | 纹理和壳层 | applyMode、采样、fallback、surfaceShell |
| `materialPolicy` | RGB/W/V 策略 | enable、mode、value、conflict |
| `modelFill` | 模型填充 | material、scope、value |
| `materialProcessProfile` | 工艺组合与验收 | RGB/W/V/support/validation |
| `materialRoleMapping` | 输入材质角色 | rules、defaultRole |
| `support` | 支撑与形态 | placement、island、shape、internalVoid、upper |
| `outerVarnish` | 模型外光油 | thickness、pixelPitch、conflict |
| `surfaceVarnish` | 模型表面光油 | inner/outer、thickness、source |
| `materialClosure` | 材料闭环 | diagnostic/repair、gap、preview |
| `preview` | 人眼预览 | format、interval、range、channels、pseudoColors |
| `relief` | 浮雕填充 | fillMode、baseZ |
| `experimental` | 安全关闭的实验能力 | OpenVDB pipeline |

## 4. 输出配置

~~~json
{
  "output": {
    "packageDir": "output/MyPackage",
    "dpiX": 600,
    "dpiY": 600,
    "layerThicknessMm": 0.028,
    "channelOrder": ["R", "G", "B", "W", "S", "V"],
    "bitDepth": 8,
    "planarConfig": "contiguous",
    "storageMode": "stripped",
    "rowsPerStrip": 64
  }
}
~~~

`storageMode=tiled` 时使用 `tileSize=[w,h]`。当前 reader 同时验证 manifest 声明和实际 TIFF storage。

禁止普通任务改变：

~~~text
channelOrder / bitDepth / planarConfig / polarity / printValue / emptyValue
~~~

## 5. 纹理与 Model Fill

legacy 示例：

~~~json
{
  "texture": {
    "enabled": true,
    "applyMode": "top_surface_band",
    "topSurfaceLayers": 1,
    "sampler": "bilinear",
    "uvAddressMode": "clamp",
    "flipV": true,
    "fallbackRgb": [0, 0, 0],
    "missingTexturePolicy": "warn_and_fallback"
  },
  "modelFill": {
    "enabled": true,
    "material": "white",
    "scope": "below_texture_surface",
    "value": 0,
    "emptyAllowedInProduction": false
  }
}
~~~

12E 诊断配置必须成对：

~~~text
texture.applyMode = global_surface_shell
modelFill.scope    = complement_of_global_texture_shell
modelFill.enabled  = true
~~~

壳层 width 必须为有限正数，step 当前固定 0.01 mm，geometry mode、minimum policy、surface scope 和 all-texture 行为都有严格枚举。

## 6. 材料工艺

`MaterialPolicy` 适合低层策略；`MaterialProcessProfile` 适合完整工艺命名与验收。启用 Profile 时：

- name/target 不能为空；
- RGB source 只能用当前支持枚举；
- white/varnish mode、coverage 和 top layers 要通过校验；
- expand/shrink 不得为负；
- support mode 当前固定复用 existing support pipeline；
- validation 中要求的通道最终必须出现。

不要在同一配置中用互相矛盾的 legacy material、policy 和 profile 表达三套不同意图。修改后必须查看 effective config 和 material process report。

## 7. 支撑

常用字段：

~~~json
{
  "support": {
    "enabled": true,
    "mode": "bottom_projection",
    "placement": "lower",
    "value": 0,
    "connectivity": 8,
    "minIslandAreaPx": 16,
    "xyDilationPx": 0,
    "internalVoid": {
      "enabled": true,
      "minAreaPx": 16,
      "fillRule": "all_internal_voids"
    },
    "shape": {
      "enabled": false,
      "preserveModelPriority": true,
      "maxAddedSupportRatio": 0.25
    }
  }
}
~~~

注意 `placement` 是否显式写入会影响兼容解析和报告的 requested/effective。

## 8. 材料闭环

只诊断：

~~~json
{
  "materialClosure": {
    "enabled": true,
    "mode": "diagnostic",
    "connectivity": 8,
    "maxGapPx": 1,
    "failOnGap": true,
    "writeGapPreview": false,
    "repair": { "enabled": false }
  }
}
~~~

修复模式必须同时满足：

~~~text
mode=repair_then_report
repair.enabled=true
maxGapPx=1
modelFill.enabled=true
support.enabled=true
~~~

## 9. Experimental OpenVDB

~~~json
{
  "experimental": {
    "openvdbPipeline": {
      "enabled": false,
      "engine": "legacy",
      "admissionMode": "strict_closed",
      "failurePolicy": "fail_fast",
      "allowNonProductionOutput": false,
      "writeProductionRgbwsv": false
    }
  }
}
~~~

默认保持全关闭。`warn_and_attempt` 不能变成 production allowed；`repair_then_strict` 必须真正执行修复后完整 strict，而不是只切换枚举。

## 10. 尚未实现的目标配置

正式决策已经定义：

~~~json
{
  "slicePipeline": {
    "mode": "legacy"
  }
}
~~~

截至基线日期，此字段是 Target State，当前 `SliceConfig` 尚未实现它。不要把目标 schema 直接加入用户配置并期待生效。

## 11. 修改配置的安全流程

1. 从最接近的 sample/profile 复制语义，不从空文件猜字段；
2. 修改输入路径和独立 packageDir，避免覆盖基线输出；
3. 明确 DPI、层厚、材料、support、closure、preview；
4. 保持协议固定项；
5. 先 `--inspect-model`；
6. 再运行 CLI；
7. 查看 effective config、manifest 和 reports；
8. 运行 RIP strict；
9. 需要对照时比较 TIFF hash，而不是只看预览；
10. 把实验配置显式标为 diagnostic/non-production。

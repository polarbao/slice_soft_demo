# 11 Qt 调试工作台

## 1. 定位

`slicer_debug_ui` 是 Qt 5.15 Widgets 调试工作台。12C 已完成 Profile、设置、effective config、统一预览和诊断区域收口，但它仍不是商业作业管理系统。

UI 的正确边界：

~~~text
编辑/生成配置
-> 启动 CLI 进程
-> 解析 progress/exit/log
-> 加载 package/manifest/reports/preview
-> 展示与诊断
~~~

它不应直接调用 OpenVDB 内部类型或读取 `slicer.cpp` 临时内存。

## 2. 主要区域

当前主工作区包含：

- “预览”页：生产层、材料叠加、调试预览；
- “配置”页：Profile、设置、磁盘差异、帮助、effective config；
- 可折叠 Diagnostics Dock：报告、曲线、日志、材料闭环等；
- 场景/项目选择区；
- 进度和运行状态。

主要组件可在 `apps/slicer_debug_ui/widgets` 和 `services` 中找到。

## 3. Profile 与场景

`samples/scenarios/slicer_scenarios.json` 是 UI 和全量样例脚本共享的场景索引，包含：

- id/display name/category；
- visibility/audience；
- configPath/packageDir；
- productionSafety；
- 是否 requires OpenVDB；
- 描述和文档入口。

普通场景默认显示，高级/fixture 需显式“显示全部场景”。场景元数据不能代替配置校验和 production admission。

## 4. Effective Config

12C 链路：

~~~text
Profile template
+ UI in-memory override
+ SliceSettingsState
-> session/slice_config.generated.json
-> ConfigValidator
-> slicer_cli
~~~

优点：

- 不覆盖原始 sample/profile；
- 每次运行有可追溯配置；
- 用户能看到本次真正生效的值；
- UI 与 CLI 仍共享 config contract。

排查“UI 设置不生效”时，先看 generated effective config，而不是只看控件状态。

## 5. 预览

统一预览使用真实 `layerIndex` 作为共享层标识。模式切换、缩放、诊断展开不应偷偷换到“最近存在的另一层”。

像素探针应展示：

~~~text
R/G/B/W/S/V 原始值
打印通道
材料语义
来源策略
~~~

伪彩图例用于理解 RGB、W、S、V 和空白，但不改变生产数据。

## 6. 材料闭环页

Qt 只读取 `reports/material_closure_report.json`，展示：

- closure status；
- confidence/source；
- production acceptance；
- repair 状态；
- 五类 gap；
- worst layers；
- 可选 gap preview。

candidate report 必须明确“不能作为生产通过依据”。点击 worst layer 应跳转真实 layerIndex。

## 7. OpenVDB 摘要

UI 可以解释 utility/candidate 报告：

- availability；
- schema 是否有效；
- production admission；
- blocker/warning；
- non-production；
- `productionReplacementAllowed=false`。

当前不应出现“OpenVDB 可用，所以自动替换 legacy”的交互。

## 8. 命令行 Smoke

~~~powershell
.\build\apps\slicer_debug_ui\Debug\slicer_debug_ui.exe --self-test
.\build\apps\slicer_debug_ui\Debug\slicer_debug_ui.exe --ui-smoke-test --case overlay-load-real --package output\UiSmokeOverlayRgbwv
~~~

`--self-test` 当前包含 startup 和 experimental report summary。UI Smoke 证明界面/数据链可运行，不是真机打印验证。

## 9. UI 开发规则

1. 长任务用进程或 worker，不阻塞主线程；
2. UI 只依赖 public core API、配置、包和报告；
3. 稳定 issue code 要保留，中文文本可以友好解释；
4. 每个显示层都使用真实 layerIndex；
5. 生产值与伪彩显示分离；
6. 小尺寸窗口要可滚动，无文本重叠；
7. 新报告先在 core 固化 schema，再加 interpreter/widget；
8. 修改后跑 targeted smoke 和必要的 12C closure。

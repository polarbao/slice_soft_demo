## 2. 目标层次与职责

| 层 | 应负责 | 不应负责 |
|---|---|---|
| Apps | 参数解析、任务编排、用户交互、进程展示 | 几何/材料算法细节 |
| Config/Profile | 解析、迁移、校验、有效配置 | 读取模型、写 TIFF |
| Importers | 把外部格式转换为场景/网格 DTO | 直接决定材料或输出 |
| Scene | 稳定领域数据 | 文件 I/O 和 UI |
| Geometry | 拓扑、相交、距离、壳层、占据 | RGBWSV、报告文件和 Qt |
| Policies | 材料、纹理、支撑、光油与准入决策 | 隐式磁盘访问 |
| Pipeline | 按顺序组合服务并传递状态 | 吞掉错误或静默回退 |
| Raster/Compose | mask 到像素/通道的确定性转换 | 决定输入是否 production-safe |
| Output/Reports | 写协议、统计和证据 | 反向决定业务策略 |

## 3. 强制依赖边界

允许：

~~~text
apps -> slicer_core 公共 API
importers -> scene
geometry -> mesh DTO + diagnostics
pipeline -> scene + geometry + materials + support + raster + output + reports
materials -> policy DTO + composition inputs
reports -> diagnostics/config snapshot/stats
~~~

禁止：

~~~text
slicer_core -> QString/QList/QObject/QWidget
importers -> TIFF writer
geometry -> material/output/report writing
materials -> 文件系统纹理加载
support -> report 文件写入
reports -> 业务决策
UI -> slicer.cpp 内部临时结构
experimental OpenVDB -> 隐式生产 RGBWSV
~~~

## 4. 当前实现与目标架构的差距

`DefaultSlicePipelineSteps()` 已定义一组正式步骤名称，但 `RunSlicePipelineLegacy()` 当前仍只是转调 `run_slicer()`。生产 legacy 数据流实际集中在 `slicer.cpp`：

~~~text
LoadConfig -> LoadModel -> Grid/Mask -> Texture -> Support
-> Compose Layer -> TIFF/Preview -> Reports/Manifest
~~~

因此当前应理解为“已有模块边界和 facade，但 legacy 实现尚未完全拆成独立步骤”。重构原则是：

~~~text
wrap first
move later
rewrite last
~~~

## 5. 两条能力路径

### Legacy 生产路径

- 默认使用；
- 不依赖 OpenVDB；
- 当前可写完整 `p0.rgbwsv.2` 包；
- 必须由回归保护。

### Global Surface Shell 诊断路径

- 当前已有配置、分区 service、CPU backend、OpenVDB conformance、纹理转移、raster mapping 和 closure 证据；
- 当前不进入生产 writer；
- 真实模型仍受 topology/repair/Release gate 阻断；
- 未来 admitted 后应复用同一 writer，不能复制第二套 TIFF 协议。

## 6. OpenVDB 边界

`USE_OPENVDB` 的 CMake 默认值为 OFF。ON 时查找 OpenVDB package 并链接；OFF 时核心和 legacy 路径仍应构建。普通 UI 不应让用户选择“CPU/OpenVDB backend”，因为 backend 是实现细节；正式产品选择的是端到端模式。

## 7. 公共 API 规则

- 使用 STL 类型或项目 DTO；
- 不把 Qt 类型泄漏到 core；
- 公开 API 变更必须分析调用方和测试；
- 文件 I/O 与算法分离；
- 错误用稳定码/结果表达，不能只打印日志；
- 单位写入字段名，如 `width_mm`、`layerThicknessMm`；
- 生产协议常量集中，不在多个模块复制魔法值。

## 8. 判断改动落点的例子

| 需求 | 正确落点 | 错误落点 |
|---|---|---|
| 新增 OBJ 属性解析 | `importers/obj` + scene DTO | UI 或 TIFF writer |
| 新增 topology issue | `geometry` + diagnostics | report writer 自行判断 |
| 新增材料优先级 | material/policy/composer | importer |
| 新增报告展示 | core report + UI interpreter/widget | UI 直接读算法内部 |
| 新增管线模式 | config + router + admission + tests | 复用 `texture.applyMode` 冒充 |
| 新增 TIFF 字段 | output contract + RIP + schema + decision | 单改 writer |

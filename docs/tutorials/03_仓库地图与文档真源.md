# 03 仓库地图与文档真源

## 1. 顶层目录

| 路径 | 责任 |
|---|---|
| `apps/slicer_cli` | legacy CLI、experimental/candidate/benchmark 命令入口 |
| `apps/rip_reader_test` | RGBWSV 包严格读取与负向验证 |
| `apps/slicer_debug_ui` | Qt 5.15 调试工作台 |
| `apps/*demo*` | 几何、OpenVDB、壳层等实验/验证入口 |

| `tests/golden/expected` | 稳定的 golden 期望 |

| `samples/models` | 小型 STL/OBJ/3MF/纹理样例 |
| `model` | 真实模型资产，使用前检查许可、大小和路径 |

## 2. `src/slicer_core` 模块地图

~~~text
config/          schema、migration、normalized config 骨架
~~~

`model.cpp`、`slicer.cpp` 和 `config.cpp` 仍承担较多 demo 时代职责。新增代码应优先落入已有正式模块，不要继续扩大聚合文件，除非改动确实属于 legacy 流程且没有合适边界。

## 3. 文档目录如何使用

| 类型 | 回答的问题 | 能否证明已实现 |
|---|---|---|
| PRD | 为什么做、用户价值和验收 | 不能 |
| DEV | 怎么设计、模块和数据流 | 不能单独证明 |
| DEMO | 如何演示和验证 | 不能单独证明 |
| ROADMAP | 先后顺序和阶段 | 不能 |
| DOC_DECISION | 已接受的长期决策 | 证明方向，不证明落地 |
| REPORT | 某阶段报告的实际结果 | 需检查命令、范围和日期 |
| TASKS/CODEX_PROMPT | 如何执行原子任务 | 不是产品事实 |
| 代码/CMake/测试 | 当前行为和边界 | A 级事实 |

## 4. 真源优先级

~~~text
当前代码、CMake、脚本、测试、fixture
> 最新且包含实际命令的阶段 REPORT
> docs/slice 正式 PRD/DEV/ROADMAP/Decision
> docs/codex_task/current
> archive 与聊天记录
~~~

示例：双模式 Decision 已接受，但当前 `config.h` 尚无 `slicePipeline.mode`，所以“有双模式目标”是真，“双模式已实现”是假。

## 6. 开始任务前的仓库检查

~~~powershell
git branch --show-current
git status --short
~~~

当前工作区可能包含用户尚未提交的功能开发。不要因为教程任务、格式化或重构而覆盖它们。只修改明确属于当前任务的文件，验证时也要区分“本次新增差异”和“进入任务前已有差异”。

## 7. 查找技巧

优先使用 `rg`：

~~~powershell
rg --files src apps tests
rg -n "ProductionAdmissionPolicy" src tests docs/slice
rg -n "global_surface_shell" .
rg -n "add_executable|add_test" CMakeLists.txt apps
~~~

查配置行为时同时看：

~~~text
config.h 默认值
config.cpp 解析和校验
samples/configs 实例
tests/unit/experimental_config 等负向测试
正式 schema/decision 文档
~~~

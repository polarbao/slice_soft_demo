# 00 阅读方法与学习路线

## 1. 先建立四个抽屉

阅读本项目时，任何结论先放进以下一个抽屉：

| 抽屉 | 含义 | 示例 |
|---|---|---|
| Current State | 当前代码确实能做什么 | legacy CLI 可写 RGBWSV TIFF |
| Target State | 已批准但尚未全部落地的方向 | 双模式 Router 和共享 writer |
| Historical State | 过去阶段为何这样演进 | 09P OpenVDB experimental path |
| Pending Confirmation | 需要真实证据或用户授权 | 12E-08D production 接入 |

最常见的新手错误，是把“有设计文档”“有 demo”“有报告字段”当作“生产功能已经可用”。在本项目中，这三者不是同一件事。

## 2. 建议学习节奏

### 第一周：会看、会跑、不会误判

1. 读完 00 至 05；
2. 查看 `CMakeLists.txt`、`src/slicer_core/config.h`、`src/slicer_core/slicer.h`；
3. 使用最小样例运行 CLI；
4. 打开 `manifest.json` 和三个关键报告；
5. 用 `rip_reader_test` 验证包；
6. 不修改生产协议，不进入 OpenVDB ON 路径。

### 第二周：理解材料和配置

1. 读完 06 至 11；
2. 对比一个 RGB-only 与一个 RGB+W+V 配置；
3. 在 Qt 工作台中查看真实 layerIndex、六通道探针和材料闭环；
4. 能解释 W、S、V 分别为何出现；
5. 能指出 preview 与生产 TIFF 的差别。

### 第三周：进入工程流程

1. 读完 12 至 16；
2. 选择一个只读、文档或测试型小任务；
3. 先执行 `git status --short`；
4. 阅读目标模块、测试和正式文档；
5. 做最小改动并运行定向验证；
6. 用实际命令结果说明完成情况。

## 3. 每次分析问题的六步法

1. **定义问题类型**：产品、配置、导入、几何、材料、输出、UI、构建还是验证。
2. **确定责任层**：不要先在 `slicer.cpp` 里找一个能插代码的位置。
3. **确定证据等级**：当前代码是 A，正式设计是 B，历史资料是 C。
4. **追踪输入输出**：输入 DTO、关键不变量、输出 DTO、错误码、报告字段。
5. **检查生产边界**：是否触碰 RGBWSV、OpenVDB、repair、准入或设备。
6. **定义验证门槛**：单测、schema、golden、RIP、UI smoke、回归、真实模型。

## 5. 如何读一份阶段文档

读 PRD 时问：

- 用户是谁；
- 问题为何重要；
- 验收口径是什么；
- 哪些明确不做。

读 DEV 时问：

- 数据流和模块边界是什么；
- 哪些是现有实现，哪些是建议设计；
- 错误和回退如何处理；
- 验证和迁移计划是什么。

读 REPORT 时问：

- 是否列出实际执行命令；
- 是 Debug 还是 Release；
- 是 generated fixture 还是真实模型；
- PASS 的范围是什么；
- 哪些项仍为 blocked、not evaluated 或 diagnostic-only。

## 6. 完成标志

完成本章后，你应该能准确说出：

> “我看到了一份双切片模式决策，但当前代码仍以 legacy 为生产路径；global_surface_shell 只具备诊断能力，不能因为配置字段或报告存在就宣称生产接入完成。”

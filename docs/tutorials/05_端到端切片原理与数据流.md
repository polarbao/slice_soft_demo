# 05 端到端切片原理与数据流

## 1. 从输入到包

~~~mermaid
flowchart LR
  A["配置 JSON"] --> B["load_slice_config<br/>normalize + validate"]
  C["OBJ/STL/3MF<br/>MTL/Texture"] --> D["load_model_report<br/>transform + orient"]
  B --> D
  D --> E["GridSpec<br/>XY pixel + Z layer"]
  E --> F["model masks"]
  F --> G["texture/material roles"]
  F --> H["support/varnish masks"]
  G --> I["compose_layer"]
  H --> I
  I --> J["RGBWSV layer buffer"]
  J --> K["TIFF layers"]
  J --> L["preview"]
  J --> M["reports + manifest"]
  K --> N["rip_reader_test"]
  M --> N
~~~

## 2. 配置加载

`load_slice_config()` 先解析 JSON，再通过 `NormalizeConfigJson()` 兼容 legacy 或 `slicer.config.1` 包装形式，填充 `SliceConfig` 默认值，最后调用校验。

关键原则：

- `input.modelPath` 必填；
- 缺省字段采用 `config.h` 的当前默认值；
- 静态不合法组合应在切片前失败；
- global/OpenVDB 等运行时不可用能力必须产生明确阻断。

## 3. 模型标准化

`load_model_report()` 完成：

1. 相对路径解析；
2. 格式自动判断或使用显式格式；
3. OBJ/STL/3MF 导入；
4. 单位、缩放、旋转和平移；
5. 可选直角自动朝向；
6. 移到构建平面附近；
7. 生成 BBox、三角形、UV、材质和输入报告。

自动朝向是几何预处理，不应被误解为完整排版、碰撞或多模型摆放。

## 4. 网格建立

当前 legacy `GridSpec` 计算：

~~~text
pixelSizeXMm = 25.4 / dpiX
pixelSizeYMm = 25.4 / dpiY
widthPx      = ceil(widthMm / pixelSizeXMm)
heightPx     = ceil(heightMm / pixelSizeYMm)
layerCount   = ceil(zMax / layerThicknessMm)
~~~

外侧光油允许 XY 扩展时，会给原点和宽高增加 padding。每一层采样 Z 为：

~~~text
zMm = (layerIndex + 0.5) * layerThicknessMm
~~~

这意味着 layerIndex 是离散标识，zMm 是物理中心位置；UI、报告和映射必须保持二者一致。

## 5. 两种 legacy 几何模式

### `closed_mesh_scanline`

每个 Z 平面与所有三角形求交，得到二维线段。对每条 Y 扫描行：

1. 求线段与扫描行交点；
2. 按 X 排序；
3. 两两配对；
4. 填充相邻交点之间的跨度。

交点为奇数通常提示开放边界、数值退化或轮廓异常，因此会记录 `oddIntersectionRows`。

### `relief_heightfield`

面向浮雕/甲片等 2.5D 模型，以 XY 列的高度或交区间构造 model mask。它适合特定形态，不等价于任意复杂闭合体切片。

## 6. 支撑与附加材料

在 model mask 基础上生成：

- 下表面/底面投影支撑；
- unsupported island 支撑；
- 可选 full vertical projection；
- 内部空洞支撑；
- 可选上表面可拆支撑；
- 外侧光油壳层；
- 模型内外表面光油 mask。

支撑形态优化可做小连通域过滤、膨胀、闭运算和 bridge，但必须保留模型优先级并限制新增比例。

## 7. 逐层材料合成

`compose_layer()` 接收该层的模型、支撑、光油、纹理列、材质角色和配置，写出每像素连续六样本：

~~~text
[R, G, B, W, S, V]
~~~

同时生成语义统计，供材料闭环、报告和 UI 使用。生产判断应优先使用语义 sidecar/exact evidence，不能只从 TIFF 颜色猜测意图。

## 8. 材料闭环

当 `materialClosure.enabled=true`：

- exact 路径从 model/support/varnish/empty 等语义 mask 判断 gap；
- `diagnostic` 只报告；
- `repair_then_report` 仅允许显式 1 像素修复，并要求 repair enabled、model fill enabled、support enabled；
- 修复后必须重新检测 remaining gap；
- 外部背景必须保持六通道 255。

TIFF inferred candidate 只能作为候选诊断，不能成为 production pass。

## 9. 输出阶段

逐层 buffer 可以：

- 写入 `layers/layer_*.tif`；
- 生成 preview PNG/PPM；
- 汇总通道、语义、支撑、纹理、材料闭环等统计；
- 写 `reports/*.json`；
- 写 `manifest.json`。

`--preview-only` 会关闭 TIFF layer 写出，但仍不是一个完整生产包。`--benchmark-core-only` 会关闭 TIFF、preview、report 文件和包发布，用于隔离计算耗时。

## 10. 概念 pipeline 与代码现实

`DefaultSlicePipelineSteps()` 给出正式步骤：

~~~text
LoadConfig
ValidateConfig
LoadInputScene
NormalizeScene
ResolveMaterials
PrepareTextureSources
ApplyTextureApplicationPolicy
PrepareVarnishGeometryPolicy
SliceGeometry
GenerateSupport
ComposeMaterialChannels
WriteRGBWSVPackage
WriteReports
ValidatePackage
~~~

当前 legacy 实现仍主要集中在 `run_slicer()`。读代码时以实际调用为准；做重构时以步骤边界为方向。

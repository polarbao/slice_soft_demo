# 12 构建、运行与调试

## 1. 环境基线

~~~text
Windows x64
MSVC
CMake >= 3.24
C++20
Qt 5.15 Widgets（仅 UI）
PowerShell
OpenVDB 可选，默认 OFF
~~~

`vcpkg.json` 声明 nlohmann-json、tiff、assimp 和可选 openvdb feature；当前顶层 CMake 的实际显式 package 查找主要是 Qt 和 OpenVDB，核心还包含项目自有 JSON/TIFF/导入实现。判断依赖是否真正参与链接时以 CMake target 为准，不能只看 manifest 名称。

## 2. 常规配置和构建

~~~powershell
cmake -S . -B build
cmake --build build --config Debug
~~~

如果 Qt 未找到，CMake 会跳过 `slicer_debug_ui`，而不是让普通 core 构建失败。

只构建常用目标：

~~~powershell
cmake --build build --config Debug --target slicer_cli rip_reader_test
cmake --build build --config Debug --target slicer_debug_ui
~~~

## 3. 运行最小样例

~~~powershell
.\build\Debug\slicer_cli.exe --config samples\configs\slice_config.json
.\build\Debug\rip_reader_test.exe --package output\SlicePackage --summary
~~~

先检查模型：

~~~powershell
.\build\Debug\slicer_cli.exe --config samples\configs\slice_config.json --inspect-model
~~~

只生成 preview/report，不写 TIFF：

~~~powershell
.\build\Debug\slicer_cli.exe --config samples\configs\slice_config.json --preview-only
~~~

注意：preview-only 不是生产包成功。

## 4. CLI 模式

| 参数 | 用途 | 生产含义 |
|---|---|---|
| 无附加模式 | legacy `run_slicer` | 当前默认生产包路径 |
| `--inspect-model` | 导入/BBox/朝向检查 | 不切片 |
| `--preview-only` | 不写 TIFF | 非完整生产包 |
| `--experimental-openvdb-shell` | 只写 experimental diagnostics | non-production |
| `--openvdb-candidate-slice` | 历史 candidate path | 必须看 nonProduction/admission |
| `--benchmark-core-only` | 关闭 I/O 做核心计时 | 不发布包 |

experimental CLI 强制不写生产 RGBWSV，并在报告中标记 diagnostic-only。

## 5. Qt 工作台

~~~powershell
.\build\apps\slicer_debug_ui\Debug\slicer_debug_ui.exe
~~~

项目已提供 `PrepareSliceSoftRuntime.ps1` 用于准备统一 runtime。具体参数以脚本帮助和 [VSCode 与 Qt 调试 UI 环境](../user_guides/VSCode与Qt调试UI运行环境说明.md) 为准。

## 6. OpenVDB ON

只有明确的 OpenVDB 任务才配置：

~~~powershell
.\scripts\configure_openvdb_vcpkg.ps1 -BuildDir build-openvdb -Triplet x64-windows
~~~

或显式：

~~~powershell
cmake -S . -B build-openvdb -DUSE_OPENVDB=ON -DCMAKE_TOOLCHAIN_FILE=<vcpkg-root>\scripts\buildsystems\vcpkg.cmake
~~~

OpenVDB 不可用时应得到明确配置错误或 `OPENVDB_UNAVAILABLE` 诊断。不要为了让普通构建通过而默认打开依赖。

## 7. 常见问题

### 找不到 Qt

- 确认 Qt 5.15 x64 MSVC；
- 使用 `Configure12CQtUi.ps1` 的已验证 lane；
- 检查 CMake cache 的 `Qt5_DIR`；
- 不把 Qt 引入 core 来“绕过”UI 构建问题。

### 找不到 package

- 对照配置实际 `output.packageDir`；
- 对照 scenario registry 和脚本期望路径；
- 检查 CLI 是否在写 manifest 前失败；
- 不把旧目录中残留包当本次结果。

### 运行很慢

- 区分 Debug/Release；
- 区分 model load、mask、support、compose、TIFF、preview、report；
- 使用 `--benchmark-core-only` 隔离 I/O；
- 不用单个 generated fixture 推导真实模型预算。

### 输出不一致

- 冻结输入/config hash；
- 确认 build type 和 feature flag；
- 按 manifest 层顺序比较 TIFF SHA-256；
- 检查 fallback、auto orient、路径和 effective config。

## 8. 调试顺序

~~~text
config parse/validate
-> model import/report
-> grid/layer index
-> model mask
-> texture/material/support masks
-> compose buffer
-> TIFF writer
-> manifest/report
-> RIP reader
-> UI presentation
~~~

从第一个失败边界入手，不要一开始就在 UI 颜色上猜几何问题。

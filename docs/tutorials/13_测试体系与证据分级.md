## 2. CTest

~~~powershell
ctest --test-dir build -C Debug --output-on-failure
~~~

当前 CMake 注册了 production admission、experimental config、geometry、material closure、support、surface shell、12E partition/transfer/raster/closure/benchmark、mesh repair contract/eligibility 等测试。实际列表以：

~~~powershell
ctest --test-dir build -C Debug -N
~~~

为准，不在教程里冻结可能变化的总数。

定向运行：

~~~powershell
ctest --test-dir build -C Debug -R "material_closure|texture_fill_partition" --output-on-failure
~~~

## 4. Schema、Golden 与 Fixture

### Schema Test

验证字段、枚举、必填项和安全默认值。适合防止 report/config 悄悄漂移。

### Golden Test

比较稳定投影，而不是所有浮点和机器相关字段。时间、工作集等环境敏感值不应直接作为精确 golden。

### Fixture

generated fixture 用于精确触发：

- boundary/non-manifold/self-intersection；
- thin wall/cavity；
- missing texture/no UV；
- overlap/gap/background；
- width sweep 单调性；
- repair eligibility。

真实模型用于验证复杂度和资产分布，但不容易定位单一规则。两者不能互相替代。

## 5. 证据分类

| 证据 | 能证明 | 不能证明 |
|---|---|---|
| unit PASS | 局部算法/契约满足用例 | 完整包和真机 |
| schema/golden PASS | 稳定契约/投影不漂移 | 所有视觉和性能 |
| RIP strict PASS | 包结构和 TIFF 协议有效 | 工艺质量、设备可打印 |
| UI smoke PASS | UI 数据链与交互 fixture 可运行 | 真机、生产性能 |
| Debug benchmark | 计时字段存在、便于定位 | Release KPI |
| generated Release | 候选算法在构造样例可测 | 真实模型预算 |
| real-model Release | 指定资产的性能/内存 | 所有客户模型 |
| downstream/真机 | 指定设备和工艺闭环 | 未覆盖设备/材料 |

## 6. 改动与最低验证

| 改动 | 最低验证 |
|---|---|
| 教程/说明文档 | 链接、格式、`git diff --check` |
| 配置解析/校验 | config 单测 + schema + 负向用例 |
| importer | 单测/fixture + model report + 旧格式回归 |
| geometry | generated 正负 fixture + determinism + strict admission |
| material/support | 单测 + golden + sample package + RIP |
| writer/manifest | reader strict + bad package + golden + legacy regression |
| Qt widget/service | target build + self-test + 定向 smoke |
| OpenVDB | OFF build + ON build + 对应 smoke/conformance |
| production path | full build + CTest + quick/full 回归 + RIP +真实模型/预算 |

## 7. 完成前检查

~~~powershell
git status --short
git diff --check
~~~

然后记录：

~~~text
运行了什么
在哪个 build/config
结果是 PASS/FAIL/SKIPPED
失败是否属于本次范围
有哪些仍未验证
~~~

不要把历史报告中的 PASS 写成本轮已运行结果。

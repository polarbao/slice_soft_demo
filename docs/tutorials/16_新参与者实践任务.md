# 16 新参与者实践任务

## 1. 实践原则

练习的目的不是尽快改 production，而是学会：

- 找到真源；
- 追踪数据；
- 识别边界；
- 写可验证的最小改动；
- 准确陈述证据。

所有练习开始前：

~~~powershell
git branch --show-current
git status --short
~~~

发现他人未提交变化时，不覆盖、不重排、不顺手格式化。

## 2. Level 0：只读认知

### 练习 A：画出一个最小包

步骤：

1. 读 `samples/configs/slice_config.json`；
2. 运行 `--inspect-model`；
3. 运行 legacy CLI；
4. 打开 manifest；
5. 查看 model/slice/support/preview 报告；
6. 运行 RIP summary；
7. 写一页笔记说明每个文件的责任。

验收：

- 能区分 TIFF、preview 和 report；
- 能说出六通道、极性、DPI、层厚；
- 不把 reader PASS 称为真机 PASS。

### 练习 B：追踪一个配置字段

任选 `layerThicknessMm`、`support.placement` 或 `materialClosure.maxGapPx`，从：

~~~text
sample JSON
-> config.h default
-> config.cpp parse
-> validation
-> runtime use
-> report field
-> unit test
~~~

输出字段生命周期图。

## 3. Level 1：无生产风险的小改动

### 练习 C：新增只读报告字段

前提：字段已有可靠 runtime 数据，不改变算法。

要求：

1. 确定 report owner；
2. 更新 schema/文档；
3. 更新 report builder；
4. 更新 unit/golden projection；
5. 不让 report 决定业务；
6. 跑定向测试和 `git diff --check`。

### 练习 D：新增 UI 帮助元数据

要求：

- 只解释已有配置；
- 不修改 core 或 production；
- 中文准确，保留稳定 enum；
- 小窗口无溢出；
- 跑 UI target、自检和相关 smoke。

## 4. Level 2：测试型任务

### 练习 E：新增一个 negative fixture

候选：

- 缺 UV；
- 缺纹理资源；
- 非法 channel order；
- layer count mismatch；
- 非法 material closure 组合。

要求：

- fixture 只触发一个主要问题；
- 断言稳定 error code；
- 不依赖模糊字符串；
- 说明 production 影响；
- 加入最小脚本/CTest 入口。

### 练习 F：验证 preview 与 TIFF

选一层：

1. 读取 manifest 中真实 layerIndex；
2. 用 UI 探针记录六通道；
3. 解释伪彩；
4. 对照 reader channel stats；
5. 说明为什么视觉颜色不能替代原始值。

## 5. Level 3：核心模块小改动

### 练习 G：新增 diagnostics 统计

选择一个不改变准入结果的计数：

- 定义 DTO 字段和单位；
- 在 owner 模块计算；
- 传到 report；
- 加 generated fixture；
- 证明 legacy TIFF hash 不变；
- 评估热路径成本。

### 练习 H：优化一个明确热点

只在 Release profile 证明热点后：

1. 冻结输入/config；
2. 记录 5 次中位数；
3. 保持算法语义和确定性；
4. 加前后结果/hash 对照；
5. 单独报告内存；
6. 不把 Debug 数值当 KPI。

## 6. 首个真实开发任务的模板

~~~markdown
## 目标
要解决的用户/工程问题。

## 当前证据
代码、测试、报告和正式文档。

## 边界
涉及的层、明确不做的内容、生产红线。

## 设计
输入 DTO、输出 DTO、不变量、错误码、兼容策略。

## 文件
精确到模块，不列无关重构。

## 验证
unit/schema/golden/RIP/UI/regression/real model 中实际需要的门槛。

## 结果
实际命令、结果、剩余风险。
~~~

## 7. 推荐的第一个贡献

优先级建议：

1. 修正文档链接或过期状态；
2. 增加只读测试/negative fixture；
3. 补充 report schema/golden；
4. 改善 UI 错误解释；
5. 小型、已定位的性能或边界修复；
6. 最后才进入 importer、geometry、composer、writer 或 production router。

一个看似小的 TIFF、极性、材料优先级或 admission 改动，实际影响下游工艺与设备，不适合作为第一个练习。

## 8. 自我检查

你准备参与正式任务时，应该能回答：

- 当前默认生产路径是什么；
- global 和 OpenVDB 各是什么角色；
- `slicingMode`、`texture.applyMode`、目标 `slicePipeline.mode` 有何区别；
- 如何从 config 追到 output；
- 为什么 candidate/exact 不同；
- 为什么 RIP reader 不是真机；
- 哪些改动需要协议决策；
- 你的改动最低要跑哪些验证。

# plan-feature：专项文档约定

每个专项一个**中文名子目录**，专项的上下文、方案、裁定与任务清单都放在自己的目录里。

## 为什么要有这个约定

在此之前，专项文档散在 `docs/` 下各处：任务卡在 `docs/codex_task/current/`，
设计在 `docs/slice/DOC/`，报告在 `docs/slice/REPORT/`，分析则可能**只躺在工作树里没入库**。
后果是接手的人要先花时间找齐，而找不齐的部分会被当作不存在。

一个专项一个目录，能从目录名一眼看出有哪些专项、各自走到哪一步。

## 文件命名

| 前缀 | 放什么 |
| --- | --- |
| `README.md` | 专项入口：一句话目标、当前结论、文档索引、状态 |
| `CONTEXT_*` | 实测现状、证据、上下文记录 |
| `ANALYSIS-NN-*` | 分项分析 |
| `DECISION-NN-*` | 裁定与依据（含用户授权留痕） |
| `PLAN_*` | 实施方案 |
| `TASKS_*` / `TASKS-NN-*` | 任务清单与逐项状态 |
| `REQ-NN-*` | 对外部协作方的能力要求 |

两种任务卡命名并存是历史原因，不强行统一——改名会打断已有的外部引用。

## 一条硬规矩：不复制真源

有的专项的任务真源在别处（例如 RIPFLOW 的清单在 `docs/codex_task/current/`）。
这种情况下，本目录里的 README **只做索引，不抄状态**。

抄一份的代价是制造第二个真源，而两个真源迟早分叉——到那时没人知道该信哪一个。

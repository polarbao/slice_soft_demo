## 20260917 变化

- `LoadLibraryA/LoadLibraryExA` 改为 UTF-8 转 UTF-16 后调用宽字符 API。
- `GetModuleFileNameA` 改为 `GetModuleFileNameW`，EXE 位于中文路径时不再混用本地代码页。
- 新增 `<wchar.h>` 并使用 `wcsrchr` 定位 EXE 目录。
- CLI 和 DLL 二进制均发生变化，不能只替换 EXE。

## 20260920 变化

- CLI 新增 `-v/--verbose`。
- 默认日志回调过滤 `RIP_LOG_DEBUG`；只有显式 `--verbose` 才输出逐像素调试日志。
- 保留 `-q/--quiet`，安静模式仍输出警告与错误。
- CLI 和 DLL 二进制再次变化。

## 20260918 中间版本

- `rip_cli.c` 与 20260917 逐字节一致，仍包含中文路径的宽字符加载修复，不包含 `--verbose`。
- `rip_cli.exe` 虽然源码相同但二进制哈希不同，可判定为重新构建产物，不能据此推断新增 CLI 合同。
- `RipSlicer.dll` 从 1,509,888 字节增至 1,510,400 字节且哈希变化；无实现源码或供应方变更说明，具体内部修改不可从头文件推断。
- 最新版仍是 20260920；0917/0918 只作为差异链和回归对照，不进入运行时选择项。

## 小型真实输入差异

使用同一 3 层 16x16 RGBWSV 输入、20260909 资源、`transparent=0` 分别运行三个中间/最新二进制：

| 模式 | 0917 vs 0918 | 0918 vs 0920 |
|---|---|---|
| `ripMode=0` | 3/3 输出 SHA-256 一致 | 3/3 一致 |
| `ripMode=1` | 3/3 输出 SHA-256 一致 | 3/3 发生变化 |

三版均 `exitCode=0` 且各输出 3 层。该结果证明 0920 不只是 CLI 日志行为变化；其 DLL 对完整流程输出也有实现更新。它不说明哪一版的工艺结果正确，因此 0920 仍须通过切片宿主的结果合同、输入不变和诊断隔离验证，物理打印正确性继续等待外部验收。

## 未变化合同

- `rip_slicer.h` 三版逐字节一致。
- `--transparent <0-4>` 与 `--ripmode <0|1>` 仍存在。
- 输入仍为切片侧冻结的 6 通道 8-bit contiguous stripped TIFF 子集。
- 输出仍由现有宿主进行命名、尺寸、通道和严格/诊断发布校验。

## 资源选择依据

新目录没有资源，因此只能显式组合或等待供应方补包。项目不能退回旧 `RIPDLL/CmykFiles`：它的 `CMYK.icc` 和 `linear.csv` 与 20260909 已验收资源不同。本次选择 20260909 资源，并把“二进制来源”和“资源来源”分别写入 provenance；若真实 RIP 验证失败则停止适配，不静默换资源。

## 证据等级

- 文件、哈希、`rip_cli.c`、`rip_slicer.h`、CLI `--help`：A 类当前输入证据。
- 供应方未提供版本说明、资源兼容声明、FileVersion/ProductVersion：缺失外部证据。
- 本地 RIP 与切片宿主测试：只能证明当前工程组合可执行，不能宣称外部生产验收完成。

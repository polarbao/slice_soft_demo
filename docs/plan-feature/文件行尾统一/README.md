# 文件行尾统一

本目录记录仓库行尾（CRLF / LF）混杂问题的现状实测、标准选型、实施方案与任务状态。

## 为什么要立专项

仓库当前**三种状态并存**，且有 176 个文件**单文件内混合**。这不是洁癖问题，它有具体代价：

- 批量改源码时锚点匹配必须行尾感知，写死一种就会 0 命中或静默改错。本专项立项前的
  一场会话里，仅此一项就导致 5 次补丁失败，其中 2 次直接造成构建失败、跑的是旧二进制。
- 单文件内混合时，「按文件主流行尾回填」这条规则本身也会出错——单行锚点没有换行符，
  推导会退化。
- diff 噪声：编辑器或工具无意归一化整个文件时，一处改动显示成全文重写。

## 当前结论

- **标准取 LF**：已是多数（1561 对 1295），且是 git 的仓内规范形态。详见方案文档的选型依据。
- **必须先补 `.gitattributes`**：现有那份只管 `*.pdf` 与一个冻结样本。没有它，
  归一化一次仍会被各人环境重新搞乱——这是结构性修复，一次性清理只是配套。
- **不能一把梭全仓归一化**：仓内已有按**精确 SHA-256 字节**校验的固定样本
  （`.gitattributes` 里那条注释即为先例），以及多处直接比对文件字节的测试。
  方案按波次执行，每波都要过字节级基线。
